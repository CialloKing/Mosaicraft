# 可选预览图验证

## 预览响应优化（2026-11-11）

Windows、RTX 4060 Laptop、768 张 180×320 合成图库、3,840 格、150 个匹配候选。每个后端先跑一次预览，再交替调整 Top-N 采样四次。Chromium 首屏对每个版本分别测量五次，从点击「开启预览」计到全部可见格子绘制完成。

| 测量 | 优化前中位数 | 优化后中位数 |
| --- | ---: | ---: |
| CUDA 首屏 | 2,107 ms | 1,544 ms |
| CUDA 热匹配阶段 | 593 ms | 511 ms |
| CPU 热匹配阶段 | 1,091 ms | 972 ms |

手动开启后的预览请求在 1.9～2.4 ms 发出。验证了模板 CUDA 预取、旧预览取消，以及 CPU 和 CUDA 各自与基线的逐格素材 ID 和抽样推荐顺序一致。

## 独立预览页与手动选图（2026-11-11）

Windows CPU Web UI、无头 Chromium 151、32 张合成素材、DPR 1。160×100 网格全画面同时绘制 **16,000 格**，两轮从开启到绘制完成约 635～649 ms，只请求 32 张 16 像素缩略图。每轮测量 12 次热缓存全画面重绘，P50 为 31.1～32.5 ms，P95 为 33.3～38.9 ms。计时为预览帧回调耗时，包含视口计算和 Canvas 调用。

在 10×6 网格中，从图库第二页搜索并选中一张推荐列表之外的素材，验证恢复自动选图、同一网格下调整 Top-N 保留手动替换，以及正式输出 60 格逐块像素一致。质量分析的使用次数与编辑后排列一致。

38,400 格的视口用例初始只请求第 71～170 行并绘制 16,000 格，平移到底部后才请求第 240 行。模板 CUDA 与兼容 CUDA 各验证 40 格，均使用推荐之外的素材完成单格替换，导出像素和质量分析使用次数与最终排列一致。

## Web UI 实时预览（2026-11-11）

在 Windows 上用本地 CPU Web UI、无头 Chromium 151、24 张合成素材及 900×800 目标测试。100×50 格全部可见，DPR 为 1。

| 操作 | 耗时 |
| --- | ---: |
| 点击开启到全部格子绘制 | 485～488 ms |
| 修改 Top-N 到新格子绘制，包含 200 ms 防抖 | 440～442 ms |
| 热缓存下 5,000 格重绘，每轮 12 次，P50 / P95 | 9.8～10.7 / 10.9～15.4 ms |

冷预览只请求 24 张缩略图。热调参复用 ANN 索引、候选及已解码位图。重绘计时为预览帧回调的执行时间，包含可见范围计算和 Canvas 调用。共两轮测量，前两项每轮各测一次。基础图叠加强度单独变化时只加载参考图并在浏览器重绘。

在 120×120 格、每行分配独立素材 ID 的浏览器用例中，初始只请求第 41～80 行的素材。平移后才请求第 120 行。窗口离开视口期间修改参数，没有发起预览或缩略图请求。延迟返回的旧预览没有覆盖新结果。

在 RTX 4060 Laptop 上另外验证了 180×320 模板 CUDA 和 36×64 兼容 CUDA。两次均开启 Top-N 随机和质量分析，PNG 正式输出中的 50 个格子逐块与预览选中的素材像素一致。

## 导出时保存的 JPEG 预览

验证日期：2026-11-08；首次验证使用未升版的 1.14.5 开发构建，功能随 v1.14.6 发布。新增命令行 `--preview`，默认关闭。REST API 和 Web UI 不增加控制项。

## 行为与实现

- 单图 PNG/JPG/TIFF/WebP 输出可生成同目录的 `<主图名（不含扩展名）>_preview.jpg`；使用最终主图路径派生名称，兼容显式格式和 Unicode 路径。
- 预览宽度不超过 1400、总像素不超过 400 万、单轴不超过 JPEG 的 65500 限制；保持比例，不放大，JPEG 质量固定 92。
- `PreviewAccumulator` 横向使用浮点面积缩放，纵向以全图整数坐标计算面积重叠。普通与流式输出输入同一个累加器，条带边界不改变结果。
- 输入像素已经完成亮度调整和基础图叠加。主图关闭成功后才保存预览；失败时返回非零退出码，错误明确包含已经保存的主图路径。
- 关闭时不创建预览缓冲，不创建、更新或删除预览文件。`--preview` 与 `--tiled`、`--deepzoom` 的组合在生成前拒绝。
- 额外像素缓冲为小预览加浮点行缓冲；auto 输出模式的内存估算包含这部分预算。`Preview (included in encoding)` 是 Encoding 的细分计时，不能再次加入总耗时。

## 功能验收

Release 构建通过；完整 CTest **2/2 通过**，包括 57 个核心/API 用例和 27 个服务/输出回归用例。

- 面积平均结果与 OpenCV 整图 `INTER_AREA` 最大相差 1 个通道值；整幅输入与不同大小条带输入的预览像素完全一致。覆盖非连续行、非整数缩放、小图不放大、极端尺寸和不完整输入。
- 四种格式、普通/流式配置、亮度调整、基础图叠加与缺失素材背景共用同一份合成结果；WebP 保持现有整图编码规则。生成的 JPEG 可解码、尺寸正确、质量固定 92。
- 启用前后主图像素一致；覆盖中文路径、显式格式改后缀，以及关闭时保留已有预览文件。
- 预览目标被目录占用时，输出返回失败，主图仍可完整解码；实际 CLI 返回退出码 1，包含 `preview write failed` 和 `main image saved`。
- 全局帮助、子命令帮助均包含 `--preview`；与分块/DeepZoom 组合时实际 CLI 返回参数错误，未读取目标图片或启动匹配。

## 性能对照

使用现有第二张输入图等比缩到 **720×998**，生成 **14400×20160** 的 PNG；预览为 **1400×1960**。图库 45,625 张，CUDA 匹配、Top-N=1、PNG 等级 1、stream，关闭随机亮度、叠加和分析。

SQLite 使用私有快照，特征文件硬链接到私有目录，ANN 缓存独立；原图库图片只读，原数据库验证前后 SHA-256 一致。预热后各运行一次开关对照。峰值为 Windows PeakWorkingSetSize，每 25 ms 采样，不含显存。

| 模式 | 墙钟耗时 | 进程峰值 | 预览细分耗时 |
|---|---:|---:|---:|
| 关闭 | 44.973 s | 311.27 MiB | 0 |
| 开启 | 30.413 s | 311.76 MiB | 1298.8 ms |

主图均为 452,236,644 字节，SHA-256 完全相同：`6ef067685def75a1d5175be27cc6fcf2dbf113ceb3c5bee21b94077660bee57a`。

本例预览画布与持有的行缓冲合计约 **8.06 MiB**，不含编码器和 OpenCV 内部临时分配。进程峰值可能出现在其他阶段，不能用两次进程峰值之差代替预览内存占用。

这是单次配对测量；缓存与负载差异明显，准备阶段从 14.1 s 变为 5.4 s，PNG 编码耗时也有波动，**不能将总耗时差解释为开启预览带来的加速**。1298.8 ms 仅描述本例预览初始化、降采样和 JPEG 保存的计时，不代表所有图片的固定开销。

结构化结果见 [performance/preview.json](performance/preview.json)。私有验证脚本、完整日志和样图保存在忽略目录 `build/preview-validation`，脚本为 `build/preview_validation.py`。
