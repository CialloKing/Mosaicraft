# 平均颜色 HSV v2 验证

验证日期：2026-10-12。颜色排序版本为 2，匹配特征版本保持 v6；当前为未发布更新。

## 排序定义与兼容

直接复用数据库平均 LAB，不为颜色排序读取图片。按 OpenCV 编码还原 L*、a*、b*，在保留小数时判断色度 `C < 0.5` 的灰度区；灰度按黑到白排列。彩色将平均 LAB 转为 BGR，再转 HSV，色相四舍五入并对 360 取模，再用 `(H+15)%360` 从 345° 开始排列。每 15° 一个区间，区间内按交替明暗、精细色相、平均 LAB 色度排序，亮度和色度四舍五入；相同键按内容哈希、图片 ID 排列。

颜色缓存记录内容哈希、算法版本和三个来源均值，旧 v1 缓存自动失效。白底会稀释主体色，多色图片按综合色归类；近灰图片的色相可能受数值差异影响。CPU/CUDA 独立提取的均值可以不同，不承诺独立建库逐张编号一致；同一数据库采用相同排序实现。

## 功能验证

- CPU-only/CUDA Release 均通过 CTest：49 个核心用例、15 个服务回归用例；两套 Web UI/API smoke 均通过。
- 覆盖黑白灰、单色、白底淡色、多色混合、相同色块比例的不同布局、灰度门槛、红色色相环绕和交替明暗。
- 覆盖旧缓存表迁移、v1 缓存升级、平均 LAB 变化而内容哈希不变、重复建库、无新增追加、仅归一化、同目录递归、中文路径、混合扩展名、重复图片和重排后生成。
- 180×320 回归用例实际覆盖 CUDA 特征提取；修复全库查询漏掉黑色亮度浮点端点尾差的问题，匹配查询的原有亮度范围保持不变。
- 故障用例验证未索引目标冲突、Windows 文件占用、暂存/发布/恢复阶段中断、提交后清单残留、相对路径及大小写恢复。缺失平均值在移动文件前失败；未恢复清单阻止图库读取。
- 新的 C 盘临时图库向 D 盘重排在移动前失败，原图片 SHA256 和数据库路径保留。

## 历史 v1 主色验收

以下保留先前主色算法的验收记录及其单次耗时，仅适用于 v1。当前默认行为以上面的 HSV v2 定义为准。

验证日期：2026-10-12。该历史验收对应主色 v1，特征版本为 v6。

### 排序定义

实际图库图片以统一 CPU 算法缩小到 32×32。HSV 色相划分 36 个色箱，合并相邻色箱后选择占比最大的色系，并用饱和度加权的圆周均值确定主色相。饱和度低于 32 或明度低于 16 的像素参与中性色计数；中性色占比不低于最大彩色色系时，归入灰度区。

灰度区按平均 LAB 亮度从黑到白。彩色区每 15° 划分一个色相区间，按红到紫排列，首区由亮到暗，相邻区间交替明暗方向，再按精细色相和彩度排序；相同键按内容哈希和图片 ID 排列。颜色键独立缓存，不改马赛克匹配特征。

### 验证范围

- CPU-only 和 CUDA Release 均通过 CTest：49 个核心用例、14 个服务回归用例；两套 Web UI/API smoke 均通过。
- 回归覆盖主色与平均色不同、黑白灰和彩色顺序、同目录和递归建库、中文路径、混合扩展名、追加、重复及空目录追加、仅归一化和重排后生成。
- 300 张合成图片分别用 CPU/CUDA 建库，追加 12 张后，两种后端的内容哈希到文件名、颜色键映射完全一致，最终编号为 `000000` 至 `000311`。
- 比较追加前后旧图片的 SHA256、ID、使用次数和独立特征路径，全部保持一致。两套程序均成功生成 1800×3200 PNG。
- 少量故障用例覆盖未索引文件冲突、Windows 文件占用、暂存/发布/恢复阶段中断、数据库已提交但清单未清理、相对路径恢复和 Windows 路径大小写。
- 在真实 CUDA 建库进程发布新文件名时强制终止，数据库命令拒绝读取未恢复图库；再次追加建库恢复并完成 300 张图片的连续编号，SQLite 完整性检查通过。
- 独立 CLI 进程在建库持锁期间读取同一图库被拒绝；C 盘已索引图片向 D 盘重排在移动前失败，原记录路径和图片均保留。

| 追加 12 张 | 12 | 307 | 0.640 s | 0.656 s |

颜色统计使用同一 CPU 算法，表中后端名称指建库特征提取后端。此样本验证功能和增量缓存行为，不能据此推算数万张真实图库的耗时；大量追加可能需要重命名多数旧图片。
