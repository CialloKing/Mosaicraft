# CPU 自动分派与工作线程：Ryzen 9 7940H

2026-11-19，Windows x64 CPU Release、Ryzen 9 7940H（8 核 16 线程），沿用[此前 AVX-512 复测](avx512-7940h-20261119.md)的私有 45,613 行图库、持久化索引、`target3.jpg`、种子 42、Top-10 与 9×16 匹配/输出格。

## 策略

- 根据用户明确要求，x64 的 CPU `fast` 在 CPU 与系统支持 AVX512-SKX 和 AVX2 时默认选 AVX-512；原复测只观察到 57,600 格的 1.62% 初筛改善，不代表各负载或各 CPU 都提速。显式基准内核覆盖和不支持时的回退不变；不改变 `auto` 的计算设备选择顺序。
- CPU `fast` 普通单图至少 14,400 格时，自动模式可以为 ANN 和基础评分使用更多逻辑线程。新增并行度受硬件线程数、每批为每个扩展后的工作线程保留至少 16 格、每线程 ANN 访问表大小约束；额外访问表占用从特征预算中扣除，最多为该预算的 1/16 且不超过 16 MiB。与特征提取线程数相同时复用线程池。显式线程数、小图、预览、分析和 GPU 调度不变。

## 只对照线程改动

基线已含 AVX-512 自动分派，两侧都固定为 AVX-512 和 `--threads 0`，不将此前的 SIMD 初筛改善叠加。时间是完整 `create` 的进程墙钟，不计私有数据库恢复和校验。先 1 次预热 / 3 对，再追加 2 次预热 / 5 对，共 8 对计时。以同轮新版/旧版之比的中位数为准，95% 区间由配对比自助法估计。

| 格数 × 候选 | 旧 → 新墙钟中位数（秒） | 配对比中位数 | 95% 区间 |
|---|---:|---:|---:|
| 57,600 × 150 | 8.636 → 8.239 | 0.9643（快 3.57%） | 0.8942–0.9815 |
| 14,400 × 600 | 5.372 → 4.870 | 0.9185（快 8.15%） | 0.8925–0.9304 |
| 900 × 150 | 1.670 → 1.714 | 1.0101（慢 1.01%） | 0.9420–1.0452 |

另行回放确认大图的 ANN 和基础评分工作槽从 8 扩到 16，900 格自动仍为 8、显式 `--threads 4` 仍为 4。全部测量 PNG 以及独立回放的 PNG、选图索引均逐字节一致。屏蔽 `AVX512-SKX` 模拟无 AVX-512：自动回退 AVX2；进一步屏蔽 AVX2 后回退标量。强制使用已屏蔽的 AVX-512 被拒绝且不生成输出。

Windows CPU 与 CUDA Release 均通过 10/10 项 CTest；未运行 Linux/macOS 测试。

[机器可读样本、分派及线程回放记录](cpu-auto-7940h-20261119.json)。计时仅描述本机的 CPU 路径和固定工作负载，不外推至其他 CPU，也不是 GPU 性能复测。

## 复现

`$avxOnlyCli` 是仅合入自动 AVX-512 分派的 Release CLI，`$newCli` 另外含线程策略变更；私有快照和索引按[前次复测](avx512-7940h-20261119.md#复现)准备。

```powershell
$trial = @('--baseline', $avxOnlyCli, '--candidate', $newCli, '--backend', 'cpu', '--prepared', $prepared,
    '--input', 'test_input_photos/target3.jpg', '--tiles', '57600', '14400', '900', '--threads', '0',
    '--baseline-setting', 'kernel=avx512', '--candidate-setting', 'kernel=avx512')
python scripts/benchmark_create.py @trial --warmups 1 --rounds 3 --output build/replay-threads-screen
python scripts/benchmark_create.py @trial --warmups 2 --rounds 8 --extend build/replay-threads-screen/report.json --output build/replay-threads-paired
```
