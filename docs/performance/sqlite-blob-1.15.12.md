# SQLite BLOB 图库：1.15.12 本地验收与性能记录

基线：`bc7c7b5b4`（1.15.11）；候选：`afd8ef877` 及本分支收尾修改。环境：Windows x64，Ryzen 9 7940H，RTX 4060 Laptop，Release，建库和生成测试使用 8 个 CPU 工作者。所有写入均指向独立测试库。原始 JSON、命令和日志保留在本地 `build/sqlite-blob-validation/`（未入库）。这些是开发机单次/抽样观察，不是隔离的重复性能准入，也不推断其他平台。

| 特征阶段（含文件发布和数据库写入） | 28.22 s | 68.07 s |
| 颜色重排 | 107.64 s | 99.67 s |
| CPU fast、ANN 首次建立时内部生成耗时 | 8.08 s | 7.38 s |
| 其中 ANN 建立 | 6.98 s | 6.45 s |
| 生成读取记录和 Grid | 0.25 s | 0.73 s |

| SQLite 主数据库逻辑字节 | 39,755,776 | 78,848,000 |

两库 CPU 标量与三种特征净载荷按 ID 计算的联合 SHA-256 均为 `a0c41c5478abad231e505e6beb0c846380486ee86db7d04519ba5a3283944703`。固定种子下 `fast`、`compatible` 合计四份 CPU 输出 PNG 逐字节相同（SHA-256 `76c3108e5bdb2d286c38ad886083a7f8d3d9e9a2498609eff9980892e751ae98`）。另用基线与新 Web 服务配对：两种评分模式各 64 格，完整的选材 ID、参考 JPEG 以及 3 个采样位置的推荐顺序（每格 60 项）和候选解释得分（每格 12 项）相同。

本次样本非素材逻辑占用减少，但 SQLite 主文件变大，读记录和 Grid 变慢，建库总耗时约增加 14%。索引的冷/热状态不同，不能将各项直接当成存储层加速比。写入细分另测独立 1,000 张追加，分 4 批：SQLite 重复检查 4.11 ms、BLOB 写入 7.86 ms、提交 8.73 ms、包含日志和素材发布的事务总计 1.75 s、颜色重排 9.59 s；这些值不能外推至 25k 或 100k。

## 100,000 张 CPU 生命周期

| 操作 | 结果 | 墙钟或进程指标 |
| --- | --- | --- |
| CPU 建库 | 100,000 张合成独立素材 | 709.55 s；归一化 39.35 s，特征阶段 240.85 s，颜色重排 426.47 s；采样峰值工作集约 568 MB |
| 固定种子生成 | 1,024 格 PNG，150 候选/格 | 11.11 s，峰值 329.95 MB；记录和 Grid 3.79 s，ANN 建立 6.89 s |
| Web 同会话冷/热 | 只改 Top-N，复用候选与基础评分 | 3.26 / 2.71 s，进程累计峰值 408.96 / 410.27 MB |
| 追加 | 1,000 张，合计 101,000 张 | 211.77 s，峰值 366.71 MB；颜色重排 208.80 s |
| `purge --apply` | 只清除 1 条已确认失踪的素材 | 9.49 s，峰值 65.81 MB |
| `report --check` | 素材与特征各 100,999 行，缺失和非法特征为 0，外键检查无错误 | 9.49 s，峰值 66.04 MB |

追加和清理后，库约 411.66 MB 逻辑大小，含 305.87 MB 数据库、94.19 MB ANN 主文件和素材等。8 KiB SQLite 页已确认。限制候选特征缓存为 **1 MiB**，在同库用 1,000 候选/格生成：缓存峰值 **1,047,536 B**，淘汰 36,315 行，读 37,111 行，SQL 查询与 BLOB 解码共 135.55 ms。与默认预算输出 PNG 逐字节相同（默认缓存峰值 7,774,928 B，读 5,908 行，19.36 ms）。这里的 1 MiB 不包含 Grid、ANN、SQLite 自身缓存或进程总内存；两次运行 ANN 建立/加载状态不同，不比较总时。冷启动只指应用会话，不等同于 OS 冷缓存。

1,000 张独立烟测另通过 CPU 建库、生成、`report --check --deep`。50 万和百万只估容量：纯特征 2,048 B/条约 1.02 / 2.05 GB；以 100,999 张实测数据库线性粗算约 1.51 / 3.03 GB，不含素材、ANN、WAL 或重排日志，未实跑这两个规模。

## 平台、恢复及发布门槛

- **Windows CPU、Web/API、Qt 与便携工程**：CPU CTest 7/7，通过完整 Web/API 脚本和 Qt offscreen（带实际 CLI），便携 HTML、搬库和确定性重绘通过。真实 1.15.11 的 `user_version=1` 图库被拒绝，测试核对数据库、图片、旧日志和 WAL 未被更改；同为 `user_version=1` 的新库正常使用。故障子进程在实际 SQLite 提交前后立即退出，`library add` 分别清理未提交文件、保留已提交文件。还覆盖 BLOB 损坏、重复追加、事务回滚、级联和 ANN 损坏重建。
- **Windows CUDA/Vulkan 实机**：各用 32 张素材显式建库并生成，均没有 CPU 回退；双后端构建的原生回归通过。生成时 CUDA 图库上传约 0.55 ms（66,752 B）；Vulkan 记录 GPU 总上传约 1.33 ms（14,984,192 B），两项口径不同。按素材摘要配对、同本机工具链编译基线，Vulkan 的三种净载荷全部逐位一致；CUDA 的 Tiny/LBP 一致，Grid 不一致。CUDA 基线自身 A/A 重建的 32 张 Grid 也均出现位差，模板内核使用浮点原子归约，本次不改算法。
- **GPU 质量门槛抽样**：25,034 张库、1,024 格、固定种子 42、Top-1/10。Vulkan 四组在选择和误差门槛内。CUDA 的误差通过，但与 CPU 对照分别有 144 / 815 格选材不同，两种评分模式均不达选材门槛；同工具链基线复现相同差数，且同模式新旧 CUDA 的选材逐格相同。该样本未完成全套实机性能门槛，**不视为 GPU 发布准入通过**。
- **未运行**：Linux 和 macOS 构建与回归、Metal 实机、GPU 全量实机性能门槛。未发布或更改已有自动后端准入状态。
