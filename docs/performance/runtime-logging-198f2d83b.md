# 运行性能日志验收（相对 198f2d83b）

2026-11-19，Windows x64 Release，Ryzen 9 7940H（8 核／16 线程），RTX 4060 Laptop GPU。使用本机私有快照和固定排列，未写真实图库。指标语义见[性能指标说明](../reference/benchmark-metrics.md)。

## 正确性与接口

- **生成：** 私有 45,613 张素材快照，900 格 × 150 候选，种子 42，自动线程；Windows CPU `fast` 实际分派到 AVX-512，CUDA 实际使用模板评分并返回 CUDA 设备事件。两个后端各自的基线、关闭和开启诊断的 PNG 字节相等；开关前后 900 个工程选图索引及素材映射独立比对一致。
- **渲染：** 固定 32×40 格排列，输出 `5760×12800`；基线、关闭和开启诊断的流式 PNG 解码像素相同。Deep Zoom 的 15 层切片数量、边缘尺寸、解码像素、清单和查看器全部相同。控制台与 JSON 的工作槽位、解码计数和放置时间在显示精度内一致。另测原生尺寸：`create` 省略未执行的缩放，`render` 保留旧键的零值。
- **追加：** CPU 和通用 CUDA 的逻辑记录（含 ID）、保留素材、Grid、Tiny/LBP 和颜色顺序一致。同目录复用扫描到 769 张，新增 1 张、查重命中 768 张，未报告编码或素材写入。CPU 与模板 CUDA 的同尺寸 PNG 报告重压缩尝试，通用 CUDA 的 72×128 场景报告新编码。
- **模板 CUDA 的既有波动：** 相同输入的基线 A/A 本身不保证新增记录 ID 和 LAB 浮点位模式稳定。按像素哈希对齐，保留素材、Tiny/LBP 和非 LAB 特征一致；A/B 的最大均值和 Grid 绝对差分别为 `4.58e−5`、`9.00e−4`，不高于这组基线 A/A 的 `4.58e−5`、`1.21e−3`。重试中还观察到颜色相近素材的相邻编号可互换；不把这条路径记作数据库逐字节一致。
- **接口：** Windows CPU/CUDA Release CTest 各 10/10。CLI 验证 `add` 接受和 `build` 拒绝 `--benchmark`；Web UI/API 冒烟通过，校验了追加模式限制、任务性能汇总、保存的请求以及生成页面的参数回填与命令生成。

## SQLite 查重占比

每个场景用 768 行种子库的新副本追加 1,024 张、请求 8 线程。低重复 32 张（3.125%，新增 992），高重复 768 张（75%，新增 256）。每行的分子和外部进程墙钟均来自同一次开启诊断的运行，不与以下关探针配对混用。

| 实际后端 | 低重复：SQL / 墙钟 | 低重复占比 | 高重复：SQL / 墙钟 | 高重复占比 |
| --- | ---: | ---: | ---: | ---: |
| CPU | 5.65 ms / 10.26 s | 0.055% | 10.68 ms / 7.88 s | 0.136% |
| 模板 CUDA | 19.25 ms / 12.25 s | 0.157% | 24.30 ms / 8.87 s | 0.274% |
| 通用 CUDA | 5.96 ms / 5.82 s | 0.103% | 8.28 ms / 2.90 s | 0.286% |

均低于 **10%** 门槛，不试换 SQL 或批量查重。模板 CUDA 两组都观察到消费者等输入。另用私有同目录图库追加 1,536 张已是目标尺寸的合成 JPEG，验证在队列背压出现时，能同时报告生产者等待和消费者等待；该样本不参加 A/B。两项均为主机等待，不等同于 GPU 空闲，也不可直接折算为可节省的墙钟。

## 默认路径开销

基线 `198f2d83b` 与候选 `5884ce1b9` 均关闭 `--benchmark` 和资源采样。每个场景 1 对预热、4 对交错采样，使用外部进程墙钟；表中比值为候选÷基线（小于 1 表示该对更快）。

| 场景 | 配对比中位数 | 单对比值范围 |
| --- | ---: | ---: |

短样本未见一致回退，不作为提速或零开销的证明。最终补丁仅在开启诊断时过滤未执行的解码/缩放项，不改变上述关探针路径；最终构建重新跑了 Release 回归。

Linux、macOS 和 Vulkan/Metal 的实机路径未在本轮重跑；便携 GPU 的追加埋点复用已回归的批处理路径。原始日志、配对数据和私有回放脚本保留在本机 `build/logging-optimization/`，不提交素材或发布制品。
