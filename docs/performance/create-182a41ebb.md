# 单次生成性能：相对 182a41ebb 的第二轮验收

本轮参照 `main@182a41ebbed358e245d2a8d8fa784a90f4fe6ee2`。以真实 `create` 进程的启动到退出（含完整输出）为首要指标；`render` 另测。不把[上一轮](create-29ac0f477.md)的已发布收益重复计入。本次没有修改自动后端选择、图库格式、候选数、选图 RNG 或 Deep Zoom。

## 哪些路径改变了

- **CPU 小图**：`fast`、普通单图、不超过 3,600 格（非预览、非排列回放）在同一 SQLite 只读事务中验证并取走匹配所需列。保留路径/特征检查、`quick_check`、既有顺序和正式任务的使用次数写入；不要求重建。CUDA 在 900 格的区间跨 1，未启用该读法。CPU 大图、`compatible` 和便携后端走原路径。
- **CUDA**：普通单图的 Ada（SM 8.9）180×320 模板、9×16 匹配格、至少 14,400 格才尝试原始目标输入和设备 Canny。其他 GPU、尺寸、预览、分析、自适应权重及非 `fast` 不据此改默认。预算不够在计算开始前尝试原同设备流水线；不会在执行失败后静默用 CPU 重算。正式门槛与实测见下。
- **建库和追加**：只降低需重新编码的图库 PNG 压缩等级；保持像素与素材身份，代价是更大的文件。
- **CPU ISA**：x64 独立编译 AVX-512；运行时检查 AVX2 与 AVX512-SKX，包含所需寄存器状态。`auto` 仍选择原 AVX2／NEON／标量，不因为“支持 512”就切换。没有为未证实的线程、缓存或布局组合增加面向用户的高性能预设。

## 测法与证据

Windows Release，Ryzen 9 7940H（8 核 16 线程）、RTX 4060 Laptop；不是 Ryzen AI 9 H 465。隔离图库 45,613 行，SHA-256 `2bd3104871fb12fa8d64dc68d15805dfbb428e459b39c36082c2e5d72508f729`，真实库不参与写入。每轮恢复快照，然后计时。照片场景均为同一目标、种子 42、Top-10、匹配/输出格 9×16；900 / 3,600 / 57,600 格各 150 候选，14,400 格为 600 候选。普通 `create` 不开逐候选诊断。原生尺寸输出另用固定排列。

[机器可读证据](create-182a41ebb.json)含每组二进制、输入/快照或排列指纹、实际后端与内核、原报告 SHA-256、每对墙钟、先后顺序和输出指纹。表列两侧各自的中位数（秒）；**区间来自逐对新版/旧版之比**，不等于两个中位数相除。正式测量 2 次预热、8 对交错；探索 1 次预热、3 对，不报置信区间，不据此启用。阶段事件、线程工时及缓存容量不相加充作墙钟。

## 建库 / 追加（不计入 create）

只将必须重新编码的图库 PNG 从无损压缩 9 调至 3；不修改原文件、不重写已有库，也不改变同尺寸同格式的原字节复制。两份 CPU Release 二进制仅该压缩等级不同。将同一批输入 PNG 放大至 200×352 后交给 CLI 归一化到 180×320，确保确实走到编码分支；8 线程，每轮独立建库并在该副本上追加。

| 输入 | 新建旧 → 新 | 追加旧 → 新 | 解释 |
|---|---:|---:|---|
| 纯 PNG，94 张新建 / 40 张追加输入 | 0.932 → 0.549 s | 0.524 → 0.328 s | 正式 8 对，配对比区间分别 0.544–0.673 / 0.543–0.690，两组均 8/8 更快 |
| 混合，178 JPG + 94 PNG 新建 / 41 JPG + 40 PNG 追加 | 1.639 → 1.132 s | 0.707 → 0.526 s | 3 对探索，仅作方向参考 |
| 纯同尺寸 JPEG，178 / 41 张 | 0.822 → 0.751 s | 0.398 → 0.324 s | 3 对，JPEG 源码未改，不归因于 PNG 优化 |

纯 PNG 新建 94 行、追加实际新增 39 行。新建吞吐（按有效行）101 → 171 张/s，追加 74 → 119 张/s。代价是 PNG 素材体积增约 **6.6%**，追加后素材从 6,998,895 → 7,463,946 B；含数据库和其他文件的整库从 7,635,016 → 8,100,068 B（约 **+6.1%**）。独立重放验证新建和追加的 ID、路径、像素哈希、匹配特征和使用计数一致，按 ID 顺序解码后的全部 RGB 也一致。不是所有来源/压缩器都具有相同的速度与空间差异。批量哈希查询未启用。

## 画质、同种子波动与资源

使用真实基线的 `fast` 对候选 `fast`，六类目标（照片、屏幕、渐变、纹理、锐利边缘、素材稀缺）× Top‑1/10 × 三个种子，共 36 对。为使验收独立于大图启用阈值，在候选构建中打开 `MOSAICRAFT_TRIAL_CUDA_TARGET` 与 `MOSAICRAFT_TRIAL_CUDA_CANNY`，用 `precision_quality_gate.py --require-device-canny` 对**每次**实际执行计数：候选每次 400/400 格，基线走原模板。36 对选图索引逐字节一致；逐组逐种子的 FP64 均值、P90/P99、半径 3 重复率、独立素材数及缺失数均通过，不是跨场景平均。

真实 CUDA 大图仍非逐次确定。57,600 格的 8 对正式测量，基线与候选分别均为 PNG `864586b4a61a…` **7 次**、`81a3afa95f02…` **1 次**，并非每一对都相同；没有剔除。两个完整哈希均已收录在[同种子排列与 FP64 对照](create-29ac0f477-variation.json)。14,400 格在该窗口两侧各 8/8 份相同。与 400 格质量矩阵分别报告，不声称 CUDA 总是确定。

单次独立带诊断回放（不是上表的正式测速）：

- CPU 900 格的图库打开/校验 **268 → 178 ms**，取行 **372 → 341 ms**，索引排列一致。新版 ANN 图库指纹/文件摘要/HNSW 反序列化分别 **51/98/100 ms**，三者已包含在 ANN 加载中。57,600 格不走新读法；其特征/ANN 查询/批量基础评分/邻域约 **2.95/1.54/0.40/1.42 s**，RSS 约 **248 MiB**。自动配置下这次回放特征/ANN 分别有 **16/8 个工作池槽位**，批次上限 1024；不是每一时刻的活跃线程数。
- 同样的 CUDA 大图：设备 Canny **57,600/57,600**，小图为 0/900。特征输入上传 **9,953,280,000 → 24,883,200 B**；设备事件上传/计算/下载 **793/1009/33 → 7/1642/43 ms**，特征阶段墙钟 **2.531 → 1.708 s**。显存上的计算时间增加，但整次任务更短。特征锁页缓冲 **44,439,552 → 202,752 B**，特征常驻设备缓冲（该工作区报告值）**2,097,152 → 85,975,040 B**，采样进程 RSS 约 **361 → 328 MiB**。不把缓冲或整卡显存采样当作进程独占显存。
- 高候选 CPU，单次诊断中的批量基础评分 AVX2 / AVX‑512 **310 / 292 ms**；最终排列一致。这是局部的一次回放，不推翻端到端八对区间跨 1 的结论。
- 相同格复用：3,600 格中截图命中 **727**，插画 **131**，照片 **24**；各自与关闭复用的选图完全一致。签名探测及逐字节确认均不足 0.4 ms。截图的特征＋ANN 查询 **328 → 273 ms**，但正式整次配对未证明更快；因此不默认启用。邻域缓存 57,600 格有约 **2,313 万**次覆盖，扩大到 256K 槽反而更慢，不能仅以冲突数更高为由继续扩容。

## 输出缓存与默认构建复核

- 同一 320 格原生排列真实 `render --benchmark`：PNG / JPEG / TIFF 各解码 320 次、缩放 0 ms；编码分别约 **729 / 78 / 479 ms**，不与工作线程工时相加。这是一次诊断，不是 JPEG 加速证据。
- 为避免直接把 RAM 默认值翻倍，用已保存 CPU 排列按行序模拟 180×320×3 的等尺寸素材缓存，末次引用后释放。对比 LRU 与已知下一次使用位置的最优淘汰，预算 512 MiB / 1 / 2 / 4 GiB：57,600 格照片均为 **5,587** 次解码，3,600 格截图和插画分别为 **1,241 / 1,793** 次，均已等于各自独立素材数。这是**串行访问轨迹模型**，不是并发渲染实测；目前不为这些任务提高 512 MiB 预算。
- 最终生成策略对基线的 CPU 短复核（各 3 对）：900 格 **1.822 → 1.725 s**；57,600 格 **9.564 → 9.798 s**，配对比 **1.025**。CPU 大图本轮没有证实提速，短测也不能证明非劣；基线与新版在两种大小的单次详细回放中选图均一致。
- 同机屏蔽 `AVX512-SKX`：自动实际选 AVX2，强制 AVX‑512 明确报错、退出 1。没有仅支持 AVX2 的第二台真机、H 465 或 Metal 真机验证。64 MiB 主机匹配预算下，CUDA 14,400 格仍全部完成，批次缩至 256，无设备回退（**不是**真实显存耗尽实验）。
- 暂无证据推出通用高性能预设。未完成 H 465 分阶段线程扫描、额外的 OpenCV 内部线程与调度组合、触发缓存压力的大图库、超大 TIFF I/O、PNG 成功区域免预填、追加批量查重及本轮 Web UI 热会话重测。下一步优先在新硬件上用真实场景验证，而不是推广单台 7940H 的结论。

最终源码默认配置（含建库改动）重新构建了 Windows CPU 与 CUDA+Vulkan 的 Release CLI、Web UI、匹配回放和测试。两套 CTest 均 **10/10** 通过。建库改动后的最终二进制指纹在 JSON `shipped` 中；各阶段性能仍绑定当时实测的二进制，不把早期样本改标成最后一次编译。

## 复现入口

在仓库根目录运行。`$r/baseline` 与 `$r/qualified` 是保存二进制的本地目录；换机器时使用对应源码、相同 Release 工具链构建，并提供自己的**隔离**图库及已准备好的索引，不可用日常图库替代。

```powershell
$r = 'build/perf-next-182a41ebb'
$prepared = 'build/backend-retest-20261118/runs'
python scripts/benchmark_create.py --baseline "$r/baseline/mosaicraft.exe" --candidate "$r/qualified/mosaicraft.exe" --backend cpu --prepared $prepared --input test_input_photos/target3.jpg --tiles 900 3600 --output "$r/replay-small"

$exe = "$r/qualified/mosaicraft.exe"
python scripts/benchmark_create.py --baseline $exe --candidate $exe --backend cpu --prepared $prepared --input test_input_photos/target3.jpg --tiles 14400 --threads 16 --baseline-setting kernel=avx2 --candidate-setting kernel=avx512 --output "$r/replay-isa"
```

CPU 试验设置只在分组子进程中生效，报告检查实际内核/已接受的值。除 `kernel` 外可分别对照 `batch`、`host_mib`、`feature_mib`、`slots`、`ways`、`feature_grain`、`score_grain`、`share`、`prefetch`、`planar`、`reuse_tiles`。这些不是发布预设；`--threads` 仍可显式覆盖。扩大缓存或启用平面布局会从匹配预算预留空间。工作池槽位不是实际 CPU 使用率，应用可控缓冲也不是整个进程 RSS。
