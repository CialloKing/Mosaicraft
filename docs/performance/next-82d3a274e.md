## 导出：Deep Zoom 通过，条带保持原样

`render` 复用固定排列，输出格 180×320、8 线程、默认质量。主场景 32×40 格，成品 5760×12800；对照 16×20 格，成品 2880×6400。

| 模式 / 场景 | 基线 → 候选（秒） | 配对比中位数 | 95% 区间 |
|---|---:|---:|---:|
| Deep Zoom，5760×12800 | 9.238 → 4.654 | 0.510 | 0.484–0.525 |
| Deep Zoom，2880×6400 | 2.550 → 1.430 | 0.541 | 0.500–0.588 |
| 流式 PNG，5760×12800 | 5.098 → 5.181 | 1.014 | 仅初筛 |
| 流式 JPEG，5760×12800 | 2.442 → 2.413 | 0.988 | 仅初筛 |
| 流式 TIFF，5760×12800 | 4.453 → 4.322 | 0.971 | 仅初筛 |

- **Deep Zoom** 两种尺寸各 8/8 对更快，所有层的切片数量、尺寸、解码像素和清单一致。复用素材写出阶段的池，少于 16 块或仅一个线程的层仍串行，不缓存解码。故障注入确认：报告切片路径、收束工作线程、保留暂存源块至发布对象清理，不写出清单或公开半成品。主场景独立诊断采样到约 38.4 MiB 的两侧峰值工作集；最高层约 4.16 → 0.64 秒、第二层约 1.28 → 0.24 秒。基线分层是控制台时间戳估计，候选为 `--benchmark` 计数；不是正式墙钟样本。
- **免预填**三种格式与各自基线的解码像素相同；显式 8 线程和自动线程分别故意让第三条带缺图；后者走双缓冲，两侧复用区域三个通道均为 64。主指标 PNG 没过初筛；补测自动线程的同尺寸 PNG 仍未通过（配对比 1.002，3 对），不默认启用。2880×6400 对照的 PNG / JPEG / TIFF 配对比分别为 0.991 / 0.992 / 0.921，均为短样本，不据此宣称提速。

## 匹配：不启用 LAB 或 ANN 候选

冻结 45,613 行图库快照并预置索引；输入 `target3.jpg`，57,600 格 × 150 候选，匹配与输出格 9×16，自动线程、种子 42、Top-10。正式 CLI 初筛不开诊断；另外逐字节比较 Lab 和逐值比较 Grid / mean，并用 `mosaicraft_match_benchmark` 回放选图索引。每轮复原私有数据库，不写源图库。

- **LAB**：四格无拼拷批量（直接缩放到共用图像的行区间）配对比 **1.065**（8.566 → 9.127 秒）；沿原 Grid 行界分条转换和累计配对比 **1.0004**（8.460 → 8.429 秒）。二者皆保持先缩放 BGR 再转 8 位 Lab，且与基线的 PNG 输出、选图索引相同。未过初筛，不继续正式 8 对及 900 / 14,400 格回退验收。
- **ANN**：CPU / CUDA 各自捕获向量，再用同一持久化索引回放各 57,600 个查询。三处搜索堆合计约 246 万次增长插入；冻结回放时增长插入段占搜索工时 **5.35% / 5.22%**（计时含该次入堆，不是纯分配），访问表池锁获取约 **0.12% / 0.11%**。未达 10%，不试堆复用、不改 `k`、`ef` 或候选次序。回放各自的选图与 PNG 指纹相同。CUDA 诊断的主机预取 `wait()` 合计约 1.81 秒，含冻结向量读取及探针开销，**不是 GPU 空转时间，也不是可直接省下的墙钟**。另跑同一 CUDA 正常构建的 3 对 A/A，配对比 0.991，全部输出指纹相同；这不证明其他输入或更长窗口没有波动。

## 图库追加：停在诊断

从同一批已归一化的 180×320 PNG 构建 768 行私有图库种子，逐次复制后追加 1,024 张，8 线程、CPU，每组 3 次独立诊断。低重复 32 张（3.125%），高重复 768 张（75%）；实际新增行数分别是 992 和 256。

| 场景 | 进程墙钟 | 归一化阶段 | PNG 编码/重压缩工时 | 算哈希 / SQL+批内查重 / 批事务 |
|---|---:|---:|---:|---:|
| 低重复 | 9.744 s | 6.650 s | 49.130 工人秒 | 144.5 / 6.7 / 62.2 ms |
| 高重复 | 7.757 s | 6.424 s | 47.781 工人秒 | 148.6 / 10.4 / 16.9 ms |

工人耗时不能与进程墙钟相加。SQL+批内查重约占墙钟 **0.07% / 0.13%**，算上哈希也仅 **1.55% / 2.08%**，均未达 10%。不改 `SELECT COUNT(*)`，不引入批量 SQL；结果只描述本次 PNG 追加负载。
