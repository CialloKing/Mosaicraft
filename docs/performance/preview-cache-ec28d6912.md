# Windows Web UI 预览：缓存扩容与特征源校验

基线 `main@ec28d6912`。Windows x64 Release，Ryzen 9 7940H / RTX 4060 Laptop。正式样本比较 **256/128/64 MiB 的缓存上限 + 最多四槽并行查验图库特征源**，不是单独扩大 RAM 的收益。计时口径是从发出 `/api/mosaic/preview` 到收到完成响应；不含启动服务器、推荐检查和浏览器绘制。诊断只在另一次运行开启。

## CPU 正式结果

45,613 行私有快照，`target3.jpg`、`fast`、种子 42、自动匹配线程、9×16 匹配块。每组 2 次预热、8 对交错；基线与候选分别启动服务，每个服务依次执行首轮、Top-N 10→5、Lab 权重 0.20→0.50。收到下一份预览后关闭上一份，模拟 Web UI 生命周期。

| 场景 | 首轮中位（秒） | 改 Top-N 中位（秒） | 改权重中位（秒） |
| --- | ---: | ---: | ---: |
| 57,600 × 150 | 12.803 → 10.589 | 11.291 → 5.699 | 11.438 → 7.487 |
| 14,400 × 600 | 8.181 → 7.318 | 6.156 → 3.689 | 6.341 → 5.003 |
| 900 × 150 | 7.095 → 4.499 | 3.627 → 2.283 | 6.843 → 4.141 |

57,600 格三项配对耗时比的自助法 95% 区间分别为 **0.814–0.842、0.501–0.520、0.643–0.671**；对照未回退。正式样本逐格素材 ID 一致。每对顺序、耗时及输出摘要见[机器可读记录](preview-cache-ec28d6912.json)。

## 内存和正确性

- 首轮容量矩阵 `128/64`、`256/64`、`128/128`、`256/128` 均保持 ANN 的 `64 MiB`。诊断中 CPU 三档格数的整份选图、参考 JPEG 和抽查推荐一致。57,600 格实际预约：评分 **145.16 MiB**，特征 **114.26 MiB**，候选 **32.96 MiB**；评分并非只占候选数组的 98.88 MiB。
- 评分命中复用基础分数，仍按顺序执行邻域惩罚与 RNG。权重变更重新评分：诊断中目标特征阶段从约 2.8 秒降为十余毫秒，原始候选继续命中。评分命中后仍需检查图库和特征源；并行化只改变文件状态采集顺序，哈希按原记录顺序归并，保留命中前查验和发布前复验。
- 57,600 格的独立 CPU 诊断里，完整档三类缓存合计约 **292.4 MiB**；进程峰值工作集约 **570 MiB**，原档约 **358 MiB**。这是诊断会话的 Windows 工作集，不等于预约量，也不是显存。旧预览固定到 A 后，新权重触发评分预算拒绝，特征和原始候选仍可复用；变更候选数重做 ANN，变更匹配格重提目标特征。低内存、预约失败、共享所有权和取消覆盖于关键回归。
- 自动范围：Windows CPU `fast`、180×320 特征图库且非分析/自适应权重。9×16 匹配块、至少 14,400 格、最多 600 候选且至多 864 万格候选单元时允许扩容；内存余量不够沿用标准档或禁用这三类保留。其他后端保持标准上限。小图的收益主要是并行校验，不是扩容。

## 未启用或未测

- **模板 CUDA**：实际特征与评分后端均为 `template_cuda`。扩容诊断中，首轮和改权重的选图一致，Top-N 重放的逐格选图摘要与基线不一致。标准档最终版复测也观察到首轮和 Top-N 摘要波动；同一旧版二进制在两次对照里的 Top-N 摘要本身也不同，不能把差异归因给扩容。尚未证明精确等价，不开启 CUDA 扩容，也不报告 CUDA 提速。兼容 CUDA 的大图配对、Vulkan、Metal、Linux / macOS 未实测。
- **Deep Zoom**：固定排列 5760×12800，8 线程，16 MiB 顶层共享边界块 LRU，切片尺寸、解码像素及 DZI 一致。独立诊断中候选解码 1,280 次，缓存命中和并发复用合计 3,040 次，驻留像素峰值约 16 MiB；但 1 次预热、3 对初筛的端到端配对中位只快 **1.55%**，未达 3% 初筛门槛。不保留导出缓存实现，不进行正式或较小对照试验。
- **快照与参考图**：不只凭数据库时间戳跳过 Tiny/LBP 校验；没有引入长期图库快照。参考 JPEG 耗时占比过低，不新增缓存。ANN 高候选扩容、五项距离分量、缩略图预算、输出素材缓存和跨任务显存常驻均保持原状。

## 验证和复现

Windows CPU/CUDA Release CTest 各 **10/10**，两套 Web UI/API 冒烟均通过；CUDA 回归要求真实设备可用。另用 Chromium 验证冷首轮、改 Top-N、改权重都绘制了更新后的画布；浏览器冒烟与诊断重叠，不作为正式性能样本。

```powershell
python scripts/benchmark_preview.py --baseline $oldWebUi --candidate $newWebUi `
  --prepared build/backend-retest-20261118/runs --input test_input_photos/target3.jpg `
  --output build/preview-cache-replay --tiles 57600 14400 900 --steps cold top weight `
  --variants both+stamps --warmups 2 --rounds 8
```

`--variants auto` 验证生产准入；`--diagnose --verify-artifacts --pin-first` 单独检查内存、参考 JPEG、推荐与固定槽。原始日志与报告在忽略目录 `build/preview-cache-20261119/`。不写真实图库，私有快照哈希前后一致；不发版。
