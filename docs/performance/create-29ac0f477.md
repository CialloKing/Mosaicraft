# 一次 `create` 的性能验收（基线 `29ac0f477`）

Windows Release，Ryzen 9 7940H、RTX 4060 Laptop (8188 MiB)。本机原始日志和保存的二进制位于 `build/perf-create-29ac0f477/`；仓库内的[配对样本与画质数据](create-29ac0f477.json)含二进制、目标和快照指纹。每个 `create` 在同一份 45,613 行的隔离数据库的**新副本**上运行，固定种子 42、Top-10、9×16 输出图块、实际写入 PNG。计时从创建 CLI 进程到其退出，不开逐候选诊断，不含数据库备份和事后哈希。与固定排列的原生输出、Web UI 连续任务、建库结果分别报告。Deep Zoom 不参与计时。

## 单次生成：相对原版的真实墙钟

两轮预热、八轮顺序交错的配对，自动线程。A 为保留现有图库格式的读取/校验/提交优化；P1 为 CPU `fast` 特征复用。下表为**组合构建实测**，不是把单项加速相加。列中是进程墙钟中位数（秒），括号是逐对“新版/原版”比值中位数的 bootstrap 95% 区间。不同窗口的绝对秒数受频率、热状态等影响，不跨表比较。

| 格数 × 候选 | CPU 原版 → P1+A | CUDA 原版 → P1+A |
|---|---:|---:|
| 900 × 150 | 2.176 → 1.770（0.798–0.844） | 2.310 → 1.972（0.783–0.909） |
| 3,600 × 150 | 2.832 → 2.251（0.793–0.843） | 2.802 → 2.330（0.814–0.859） |
| 57,600 × 150 | 10.779 → 9.342（0.865–0.887） | 7.862 → 7.348（0.930–0.951） |
| 14,400 × 600 | 6.157 → 5.322（0.850–0.898） | 4.759 → 4.472（0.895–0.938） |

单项对照（同规模顺序）：A 单独的 CPU 配对比为 **0.820 / 0.836 / 0.961 / 0.935**，CUDA 为 **0.852 / 0.865 / 0.944 / 0.922**，八个区间上界都低于 1。P1 单独的自动线程 24 对结果见 `p1-auto24`：重负载 15.511 → 14.600 s；900 格区间跨 1，不声称小任务的 P1 加速。保留旧格式，无需重建、无新磁盘副本要求；B 权威特征包尚未验收。

**画质：**组合对照每个后端六类目标 × Top-1/10 × 三种子，原版和新版均为 `fast`。CPU 与 CUDA 各 12/12 组通过逐种子 FP64 均值、P90、P99、覆盖率、半径 3 重复和独立素材检查。CPU 四组计时样本 PNG 完全相同。CUDA 在 57,600 格不保证逐像素重复：A 单独八个正式候选样本有三种哈希（4/2/2），组合也出现了变化。无样本从耗时区间剔除；小规模画质门槛通过不等于大图像素一致。

## 独立场景与取舍

| 比较 | 工作量 | 原版 → 候选中位数 | 结论 |
|---|---|---:|---|
| CUDA 原始目标上传、CPU Canny | 57,600 × 150 | 12.632 → 13.835 s | 上传 9,953,280,000 → 24,883,200 B，却更慢（1.061–1.223）；保留旧 CUDA 路径 |
| 便携 HTML 有界导出 | 相同排列 320 格，180×320，8 线程 | 2.702 → 1.516 s | 保留；清单、输出大小一致，工程检查通过 |
| 流式 PNG / JPEG 重叠编码 | 同一原生排列 | PNG 1.896 → 1.859；JPEG 0.845 → 0.853 s | 区间跨 1，未默认启用；无压缩 TIFF 为对照，不计为提速 |
| 仅流式 PNG 固定 Sub | 同一原生排列、关闭重叠 | 1.575 → 1.335 s | 解码像素一致；28,907,550 → 30,889,564 B（+6.9%），速度不等于无代价 |
| CPU 建库仅并行哈希 | 建 272 张 / 追加 80 张，含重复输入 | 建库 1.260 → 1.107；追加 0.561 → 0.471 s | 身份、特征及行数一致；追加区间上界 1.132，未达默认准入 |
| 在并行哈希之上双缓冲 | 同上 | 建库 1.306 → 1.456；追加 0.522 → 0.643 s | 均显著更慢；不默认启用 |

ANN 直接写批次在 CPU、8 线程、八对的四个区间均跨 1，不能据此宣称提速。模板设备 Canny 的早期组合探索仅有两对，不能代替内核特化后的独立验收。Vulkan、Metal、不同 GPU 架构、常驻 GPU 图库均无本轮速度承诺。

## 复核

- `scripts/benchmark_create.py`：用保存的 `baseline`、`layout-a`、`p1` 或 `combo` 中的 CLI 和 `build/backend-retest-20261118/runs` 重放。`--extend` 检查输入和二进制指纹，不用新二进制重标历史数据。
- `scripts/precision_quality_gate.py --baseline-match ...`：逐种子比较同后端的两个 `fast`；与旧 `compatible` 的比较不代替此门槛。
- `scripts/benchmark_render.py`、`scripts/benchmark_library_build.py`、`scripts/benchmark_hot_jobs.py`：固定排列、独立新建/追加、同进程连续正式任务分别测量。不要同时运行性能测试。GPU 事件、异步等待与 CPU 的时间可能重叠，不相加作为墙钟。
