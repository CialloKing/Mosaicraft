# 单次生成：CPU 大图邻域去重与 LAB 特征

基线 `main@49bde5f5b`（不重复计算[上轮收益](create-182a41ebb.md)）。以一次真实 `create` 从启动到完整 PNG 落盘并退出的墙钟为准。测试环境是 Windows x64 Release、Ryzen 9 7940H（8 核 16 线程）、RTX 4060 Laptop，自动线程；不能外推到所有架构。

## 跳过不可能相似的邻居

每个候选原本可能与最近 50 个成功选图逐一查重。现在用 50 位掩码维护四个 Grid-LAB 坐标的值域。若任一坐标中间隔了一个完整的 16 单位桶，单通道的最小加权平方差已超过整格阈值（`0.010 × 64 × 100 = 64`）。只有不能排除的邻居才查原缓存、用原距离确认；不是用四个坐标代替全量特征打分。没有改候选数、阈值、惩罚顺序、选图顺序或 RNG。每个启用任务只需约 0.8 KiB，计入主机匹配预算，不为每张图库素材复制特征。

同一份 45,613 行的隔离快照，逐轮重置使用统计；照片 `target3.jpg`，匹配块与输出块 9×16，种子 42，随机 Top-10。每组预热 2 次、8 对交错正式计时。两侧列各自的墙钟中位数；区间是**逐对新版/旧版**的自助法 95% 区间，不是两列相除。每对毫秒数、先后顺序、输出与二进制 SHA-256 在[机器可读记录](create-49bde5f5b.json)中。

| 后端、负载 | 基线 → 启用过滤（秒） | 配对比 95% 区间 | 更快对数 | 默认决定 |
|---|---:|---:|---:|---|
| CPU，57,600 格 × 150 | 8.756 → 7.928 | 0.880–0.913 | 8/8 | 启用 |
| CPU，14,400 格 × 600 | 4.755 → 4.524 | 0.940–0.964 | 7/8 | 启用 |
| CUDA，57,600 格 × 150 | 5.813 → 5.854 | 0.983–1.020 | 2/8 | 不启用 |
| CUDA，14,400 格 × 600 | 3.873 → 3.851 | 0.940–1.013 | 4/8 | 不启用 |

正式计时使用带过滤器的试验二进制（CPU/CUDA 各自对照同一基线），不是把最终默认版描述为在 CUDA 上也开启。生产仅在 CPU `fast`、至少 14,400 格、普通单图生成启用；CPU 小图、`compatible`、CUDA、Vulkan、Metal、预览、固定排列和 Deep Zoom 继续走原查重逻辑。

### 单独诊断与画质

开启分阶段计数再回放，不混入正式计时。CPU 照片 57,600 格：实际距离调用 **23,200,522 → 1,139,959**，查表命中 **64,089,403 → 12,916,291**；命中数下降是因为这些查找不必再做。邻域 **1.095 → 0.454 秒**；同一对的进程峰值 RSS 为 248.8 → 249.1 MiB，不把一次 RSS 差归因于过滤器。CPU 屏幕图 14,400 格、Top-1：距离调用 395,427 → 5,306，邻域 0.262 → 0.226 秒。两组新旧选图索引和 PNG 均逐字节相同，无缺失、无警告。测试也对照同桶、跨桶、非有限值、无效特征、窗口过期和回放后的惩罚。

CUDA 照片正式 8 对内，两个格数的所有对应输出相同。但在**另一次带诊断回放**，大图 PNG 从 `864586b4a61a…` 变为 `e2afdcc915bd…`，57,600 格中有 16,040 格索引不同（首个差异为零基 37,174）。两个输出都在历史记录出现过；这不证明本次波动的具体成因，也不宣称 CUDA 同种子逐次确定。异常样本没有剔除。虽然实验的 CUDA 邻域阶段 0.942 → 0.301 秒，下一批的特征与 ANN 可重叠运行，**整次任务并未证实变快**，所以不改 CUDA 默认。

## CPU 特征：精确的列累加

旧 `fast` 特征对每个原生图块的 64 个小 ROI 分别调用通用 `sum`。列累加版先在每个 Grid 行内连续读取 LAB 字节，用无符号 16 位整数保存每列总和，再按原边界汇入每格的三个通道和。每列最多 257 行（`257 × 255 = 65535`），更高或过宽回退；仍使用原分母和浮点乘法。最多 3 KiB 栈暂存/活跃线程，不随格数或图库扩大。非连续步长、窄图、空边格、横竖尺寸、纯白累加上限和超界回退都对照了原均值与 192 个 Grid 分量。

以**只开邻域优化的 CPU 构建**为参照，不是与 `49bde5f5b` 跨窗口相减。1 次预热/3 对初筛后独立做 2 次预热/8 对正式对照：

| 负载 | 原求和 → 列累加（秒） | 配对比 95% 区间 | 更快对数 | 默认决定 |
|---|---:|---:|---:|---|
| 57,600 格 × 150 | 7.921 → 7.618 | 0.9414–0.9725 | 8/8 | 在 ≥57,600 格且原生特征 180×320 时启用 |
| 14,400 格 × 600 | 4.739 → 4.611 | 0.93838–**1.00005** | 6/8 | 不能证明更快，仍用原求和；仅开邻域优化 |

两次独立 CPU 回放的排列与 PNG 均相同。57,600 格的特征阶段由 2.766 降至 2.490 秒，14,400 格屏幕图由 0.748 降至 0.673 秒。后者不覆盖真实 `create` 的启动、编码等成本，不能取代正式门槛。

最终版还校正了一个诊断口径：旧 `LAB` 工人时间含 `BGR→Lab` **以及**合并的 Grid/均值，新版明确分开，沿用原有计时点数。最终 CPU 照片回放得到特征墙钟 **2.434 秒**、ANN **1.304 秒**、贴图 **0.676 秒**、编码 **0.596 秒**；其中颜色转换累计 **15.354 工人秒**、Grid 加均值累计 **0.802 工人秒**，这两个数不能和墙钟相加。正式默认的诊断确认两种大图均预留 **792 字节**过滤器，只有 57,600 格开启列累加；CUDA 两项均关闭。

## 哪些优化已经到位，下一步测什么

- **CPU 基础评分**已有并行与 SIMD；在这台机器上，不能用 AVX-512 的局部吞吐代替整次 `create` 收益。小图已经减少重复读库，大图现在减少邻域查重。分项计时已表明应先研究 `BGR→Lab`，而非继续压榨网格求和。先对照完全相同的 8 位输出，再测整次；不以近似色彩转换换速度。
- **CPU 与 CUDA 共用的 ANN**：先量检索内部的临时堆分配、每批等待和有效并发，再试复用每工作线程的查找暂存。固定 `k`、图库顺序、近邻搜索参数及平局次序，用逐格候选验证；不要重做已有的批量接口，也不要为测速减少搜索深度。
- **CUDA**：大图原始传输和设备 Canny 已在上轮的特定 Ada 模板范围内启用。此次即使缩短邻域阶段也没缩短墙钟；下一步看 GPU 等待下一批 ANN 的空档、主机同步与非模板成本，不优先改仅约 0.15 秒的候选评分。
- **原生大图、热会话、建库是不同任务**：固定排列分别量 PNG/JPEG/TIFF 的编码与盘速，再决定是否改条带流水线。已有热会话缓存和 PNG 建库优化，本轮没改、没重测，不给它们记新收益。没有证据要更改图库格式、默认线程数或扩大缓存。
