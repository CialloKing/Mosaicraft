# 全项目匹配优化报告

日期：2026-11-18。此报告记录本地源码的 M0-M4 交付；不代表 v1.15.7 已发布包行为。对照基线为 `c9d1d2dc9909a55a03516aec660eb72b6d0009ba`。

## 结论

CPU、CUDA、RTX 4060 Vulkan 与 Radeon 780M Vulkan 均通过本计划的端到端速度门槛；48 个设备/目标/Top-N 画质组全部通过。新请求和 CLI 默认值已切换到 `fast`，显式 `compatible` 保留，各后端的自动选择策略没有改变。Web UI 恢复缺少 `scoreMode` 的旧历史请求时仍使用 `compatible`；已保存选图直接渲染，不重新匹配。

## 实施

- **M0**：匹配基准可关闭逐候选诊断；诊断报告邻域候选、相似度缓存命中、Grid 实际距离、早停及剪枝数。
- **M1**：邻域频次与最近使用位置改用图库下标连续数组。Top-N 入围分数只在新分数严格差于当前门槛时剪掉只会增加分数的 Grid 相似检查；平分、预览推荐长度及完整分析路径维持原规则。
- **M2**：批次特征先固定，再由现有线程池并行计算只读候选基础分；邻域、排序和使用历史仍顺序执行。批次读缓存预算不足时缩批或回退串行路径。
- **M3**：CPU 快速路径用 FP32 特征距离和加权分，Tiny 使用精确整数平方和；x64 使用 OpenCV 运行时 AVX2 检测，支持时调用独立 AVX2 编译单元，否则走标量。CUDA 模板/通用内核与 Vulkan/Metal 快速路径输出每候选一个 FP32 基础分；兼容模式继续使用原路径。按每格最小使用次数居中合成历史惩罚，极大跨度提升为 FP64。
- **M4**：CLI/API 新请求、核心配置和 Web UI 新建表单默认为 `fast`。实际后端和精度内核版本纳入运行记录及评分缓存代次；旧历史恢复保持 compatible。

不改图库格式、候选数、随机选取规则或后端自动策略；不把素材 ID、使用次数或输出计数改为浮点。GPU 设备搬运、常驻图库缓存、输出和建库优化不属于本轮。

## 性能

最终性能候选使用 Windows Release、Ryzen 9 7940H、8 个工作线程、隔离私有图库。每后端先预热 2 次，再按平衡顺序正式采样 8 轮；小任务不确定的 CUDA 与 RTX Vulkan 另补 24 轮。旧版 compatible 与新版 fast 交错执行，每次新进程并恢复图库数据库，计时关闭详细邻域统计。数值是完整任务墙钟中位数，包含匹配及输出；括号内是同轮新旧耗时比的中位数加速比例，因此受两列各自的边际中位数与配对中位数差异影响，百分比不会严格等于表中两时间直接相除。它衡量 M1-M3 合并后的收益，不把总收益单独归因于 FP32。

| 后端 | 900 格 | 3,600 格 | 57,600 格 × 150 候选 | 14,400 格 × 600 候选 |
|---|---:|---:|---:|---:|
| CPU | 1.859 → 1.700 秒（9.1%） | 3.009 → 2.329 秒（22.3%） | 24.098 → 13.846 秒（41.4%） | 21.368 → 6.464 秒（69.6%） |
| CUDA RTX 4060 | 2.008 → 1.865 秒（7.4%） | 2.815 → 2.374 秒（14.4%） | 14.316 → 8.783 秒（37.2%） | 13.525 → 5.023 秒（63.4%） |
| Vulkan RTX 4060 | 2.315 → 2.370 秒（配对持平） | 3.781 → 3.102 秒（17.9%） | 37.481 → 25.427 秒（31.8%） | 22.824 → 7.331 秒（67.9%） |
| Vulkan Radeon 780M | 2.325 → 2.409 秒（慢 2.2%） | 4.004 → 3.272 秒（19.0%） | 29.144 → 19.033 秒（34.7%） | 21.050 → 9.322 秒（56.0%） |

按程序的逐轮配对比率 bootstrap 95% 区间，900 格 CUDA 的 24 轮比率为 0.949 `[0.932, 0.969]`，约快 5.1%；RTX Vulkan 的 24 轮比率为 1.010 `[0.975, 1.022]`，约慢 1.0%。Radeon Vulkan 的 8 轮区间上界为 1.027，即慢不超过 2.7%。均在小任务最多回退 5% 的门槛内。各后端重负载场景 8 轮配对区间均显示至少 13% 的加速。

单独的详细诊断回放用于解释邻域路径，不用于上述生产速度门槛：14,400 格 × 600 候选中，8,640,000 个邻域候选有 8,203,493 个严格剪枝（95.0%）。诊断计时的完整任务从旧版 24.75 秒降至 M1 14.01 秒、M2 7.75 秒；邻域计时分别为 10.63、1.18、0.72 秒。M1/M2 阶段回放在 900 格与 14,400 格场景均逐格选图一致。因为这组开启了细粒度计数，不应与未插桩端到端采样混算。

## 画质与验证

在 photo、screen、gradient、texture、edge、scarce 六类固定目标上，以三个固定种子和 Top-1/Top-10 对比每个后端的 compatible/fast，共 288 次匹配、144 对结果。48 个设备/目标/Top-N 组全部通过：统一高精度评估器的均值、P90、P99 未升高；未匹配数未增加；半径 3 素材重复率未增加；独立素材数未下降。所有 144 对固定种子的选图索引相同。该结果不构成逐格一致性承诺。

最终评分候选 SHA-256：旧版基准 `117e1a932c4bf1c7eb562bc978af631356d4e2c2a41885bf4892d9423a94a2e0`；fast 候选 `d58f99094e7da233e5cc03b7420f5de8b503df830053ba6a40fc582519c564fa`。Windows CPU-only 与 CUDA+Vulkan Release 配置均构建成功，CTest 各 10/10 通过。质量报告实际 CPU 内核标记为 `cpu-v6:fp32-v3-avx2`。Metal、Linux GPU、Apple GPU 没有实机验收，标记为 not-run；fast 默认不会让 Vulkan/Metal 进入 auto。

本机原始阶段报告位于忽略的 `build/precision-rollout-c9d1d2dc9/`，性能摘要为 `perf-{cpu,cuda,vk-nv}/report.json`、`perf-final-vk-amd/report.json`，24 轮补测在 `perf-*-small-24-final/report.json`，48 组画质门槛在 `quality/gate.json`。它们保留完整样本、配对区间、二进制和图库快照身份。
