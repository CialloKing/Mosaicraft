# 文档维护

文档先按读者要完成的任务分类，再按主题拆页。根 README 只保留项目介绍、下载、首次运行和导航；[文档中心](../README.md)是完整入口。

## 目录约定

| 目录 | 保存内容 |
| --- | --- |
| guides/ | 当前用户操作、命令、界面、图库与工程 |
| reference/ | HTTP API 等精确接口参考 |
| development/ | 构建、架构、打包、发布与维护规则 |
| archive/ | 不再作为当前指南的版本、验收、性能和研究记录 |
| performance/ | 原始 JSON/SVG；路径与内容保持稳定 |
| releases.md | 当前源码变更摘要、发布状态及兼容边界 |

third_party 内 SOURCE.md 与许可证属于依赖来源声明，保留在依赖旁；不移入历史档案。

## 更新规则

1. 功能变更更新对应当前指南；接口字段以实现为准，CLI 参数以 cli-options.json 为准，版本以 contracts.json 为准。
2. 版本摘要只描述当前源码和已核实的发布状态，不将候选能力写成稳定包能力。
3. 完成的测量保留环境、输入、版本、样本范围和 not-run 状态。历史报告只修导航与明显的分类问题，不改写当时数据或旧命令。
4. 新页面必须加入文档中心，或加入从它可达的专题索引。避免再创建大而全的百科或逐次堆叠指南。
5. 文档相对链接按所在文件解析，Shell 代码块按仓库根或解压目录执行，二者不要混用。

## 检查与打包

```sh
python scripts/check-docs.py
python scripts/check-docs.py --root <解压目录>
```

检查本地 Markdown 链接、锚点和页面可达性，不联网探测外链。日常 CI 的 Linux job 和安装了 Python 的 CTest 均复用此检查，新增页面或失效链接会使检查失败。二进制包也复制完整 docs/ 树，保持相同导航与相对路径。命令、参数、平台能力变更仍需对应功能测试，链接检查不能验证程序行为。

源码文件引用优先使用行内路径说明；需要可点击代码链接时使用仓库链接，避免二进制包内出现指向未交付源码的相对链接。历史数据中的绝对路径只作为当时的证据，不改写成可运行示例。

保留 docs/API.md 与 docs/ENCYCLOPEDIA.md 两个旧入口用于导航，新增文档不得继续向旧入口堆叠内容。
