# 架构与数据契约

本页描述当前源码的边界。细节以 contracts.json、cli-options.json 和实现为准；旧版本的逐次演进保留在[历史百科](../archive/releases/encyclopedia.md)。

## 两个入口，共用服务

CLI 从 src/main.cpp 进入，Web UI 与 HTTP API 从 src/server.cpp 进入；两者复用 core 中的建库、生成、预览、检查和工程服务。CLI 选项定义集中在 cli-options.json，避免命令行和页面重复维护参数定义。HTTP 端点及请求字段见[接口参考](../reference/api.md)。

## 建库与图库读取

建库沿用图像解码、归一化、特征统计、数据库与特征缓存发布的流程。SQLite 保存素材元数据与使用统计；特征文件、FeaturePack、ANN 和颜色顺序数据有各自的契约边界。图库资源路径相对数据库目录解析，普通命令参数相对工作目录解析。

完整复制图库见[搬移图库](../guides/portable-libraries.md)。版本不匹配时使用原有校验，不通过修改标记绕过检查。

## 生成与选图

1. 预处理目标图，按匹配网格提取 AvgLAB、Grid、TinyImage、边缘密度和 LBP。
2. 沿用既有 ANN 和亮度范围规则生成候选。
3. 计算候选距离，合成权重、历史使用惩罚，再执行邻域处理、排序和随机选图。
4. 将最终排列交给合成与输出流程，成功后记录对应使用情况。

预览与正式生成复用既有选图流程和缓存身份；后端、设备、评分模式及内核版本改变时不能复用不兼容的结果。HTML 工程保存排列与使用资源，render 按固定排列回导，无须重新匹配或访问原图库。

## 计算后端与资源

compute/ComputeBackend.h 定义设备、能力和会话边界。CUDA 通过适配器保留原工作区和计算实现；PortableCompute 共用 Vulkan/Metal 的预处理、收尾与数据布局，原生缓冲和同步留在各后端内部。

任务按批次调度计算，复用任务工作区、图库上传和管线；CPU 线程预算、GPU 暂存和常驻图库分别计量。共享缓冲按同一分配解释，不能重复累加为物理内存。不可取得的指标显示不可用。

后端及回退规则见[GPU 指南](../guides/gpu-backends.md)，精度、同步、预算和验收边界见[四后端实现](portable-gpu.md)。

## 输出与失败边界

单图、HTML、Deep Zoom 和分块输出复用既有规划、编码与发布逻辑。工程及归档先暂存再发布，覆盖按输出所有权检查；批次执行错误不应提交部分图库事务或对外发布不完整工程。取消和运行故障沿用任务生命周期传播。

便携工程仅使用当前内部结构，不设置独立格式版本；其资源校验与目录结构见[便携工程](../guides/portable-projects.md)。

## 版本的唯一来源

软件、API、图库及特征等版本值统一来自根目录 contracts.json。CMake 与代码使用生成值，文档在[版本状态](../releases.md)解释公开状态和兼容边界，不另造一套版本体系。当前 FeaturePack 契约为 1，历史百科中的旧代际名称不代表当前契约编号。

研究、历史测试数量和性能样本分别在[历史档案](../archive/README.md)与[原始数据](../performance/README.md)中维护，不能替代当前回归或准入结果。
