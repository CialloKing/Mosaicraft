# v1.14.1 选图提速与内存收敛验收报告

测量日期：2026-10-08。交付类型：Windows x64 发布候选。

## 结论

本机固定样本达到三个性能目标：普通 GPU 场景选图阶段降低 **87.5%～88.2%**，普通 CPU 场景总耗时降低 **32.3%**，普通流式 PNG 峰值内存降低 **37.0%**。三个场景的普通/分析模式共六组比较均提速，没有超过 5% 的总耗时回退。

五种特征、权重、邻域规则与 CLI/API 默认参数保持不变。PNG 过滤、压缩和每 1000 行刷新策略保持不变。六组新旧输出文件 SHA256 分别完全一致；质量分数在日志显示精度内一致。PNG 编码阶段变化较小，不将整体提速归因于编码器加速。

## 方法与环境

- 基线：v1.14.0 RC1，提交 `5d1bf77e5e940cf855e06aa77d733622e8758c9a`，使用实现前保存的独立二进制。
- 新版测量实现：`077653758477c3d20f8c977f13fe667d70ca32f0`；之后仅增加独立基准工具和文档。最终候选包提交见包内 `BUILD_INFO.txt`。
- 数据：45,625 张图库快照、`test_input_photos/target5.png`；数据库、目标图和二进制 SHA256，以及逐次结果见 [原始记录](performance/v1.14.1.json)。原图库未修改；运行数据库和特征校验元数据位于私有工作目录。
- 参数：固定 `--topn-random 1 --benchmark`，关闭颜色调整。`--analysis-mode both` 分别执行普通与分析模式；每次恢复相同数据库使用计数。新旧版本交替运行，各预热一次，再各测三次取中位数。共 12 次预热、36 次正式运行。
- CUDA JPG batch / PNG stream：13,482 小块，输出 22680 × 34240。CPU JPG batch：`--cpu --out-w 360 --out-h 640`，1,600 小块，输出 7200 × 12800。
- 硬件/软件：Ryzen 9 7940H（8 核/16 线程）、31.22 GiB 可见内存、RTX 4060 Laptop 8 GiB；Windows 10 19045、驱动 616.92、CUDA 13.3.33、VS 2026 Release。
- 总耗时为进程墙钟时间，包含启动、分析和输出，以及最多约一次采样轮询延迟。结果是本机本样本测量，不代表所有图库。热运行已建立 ANN 与特征校验缓存；首次建立 `features.meta` 需要读取候选源文件。

## 收益来源

### 选图

普通 GPU JPG 的 Selection 中位数为 **8292.0 → 981.0 ms**，降低 88.2%；普通 GPU PNG 为 **7838.1 → 979.4 ms**，降低 87.5%。提前退出保持原累加和归一化顺序，图片对缓存使用完整键校验，窗口和选图仍顺序更新。

普通 CPU 新版候选特征加载为 **354.0 ms**，评分及邻域处理为 **380.6 ms**。旧 CPU scoring 为 **2502.7 ms**，其中包含逐文件加载和邻域处理，不能将两者直接当作纯评分内核对比。兼容保留的 Selection 字段在 CPU 路径包含特征预载，查看细分字段时不能重复求和。

### CPU 特征读取独立对比

独立工具使用同一批 **15,995** 张候选，在排除评分与输出后比较逐文件读取和经过校验的包读取。预热后交替运行三次：

| 方式 | 三次结果 | 中位数 |
|---|---|---:|
| 逐文件读取 | 1290.700 / 1360.740 / 1346.230 ms | 1346.230 ms |
| 校验后的特征包 | 318.238 / 371.346 / 439.489 ms | 371.346 ms |

读取耗时降低 **72.4%**。连续缓冲只保留候选涉及的特征；包记录和源文件校验不通过时分别回退，缺失 TinyImage/LBP 不会当作有效零向量。校验元数据可丢弃，现有 v2 包、数据库和 GPU 特征加载逻辑保持兼容；失效记录直接使用源文件，不强制重建图库。

### PNG 输出

普通 PNG Encoding 中位数为 **53131.7 → 52310.0 ms**，变化约 1.5%；分析模式为 **54676.3 → 52218.0 ms**。多行写入减少接口调用，但编码仍是主耗时，不能据此声称大幅 PNG 编码提速。

新版普通 PNG 的颜色转换中位数为 246.4 ms，行编码为 52062.6 ms，生产者等待为 50499.4 ms，消费者等待为 20.1 ms。贴图和编码重叠，工作线程加载时间是累加值，等待时间和子阶段不能与墙钟时间直接相加。

PNG 文件均为 **1,243,874,444 字节**；CUDA JPG 均为 **590,378,322 字节**；CPU JPG 均为 **73,198,308 字节**。没有通过增大文件体积换取速度。

## 内存

进程峰值取三次正式运行的最大值，单位 MiB，口径为 Windows PeakWorkingSetSize。

| 场景 | 模式 | v1.14.0 | v1.14.1 | 变化 |
|---|---|---:|---:|---:|
| CUDA JPG | 普通 | 3353.70 | 3358.29 | +4.58 |
| CUDA JPG | 分析 | 3358.06 | 3361.03 | +2.97 |
| CUDA PNG | 普通 | 675.49 | 425.58 | -249.91（-37.0%） |
| CUDA PNG | 分析 | 680.21 | 430.65 | -249.57（-36.7%） |
| CPU JPG | 普通 | 519.62 | 481.55 | -38.06（-7.3%） |
| CPU JPG | 分析 | 519.12 | 482.20 | -36.92（-7.1%） |

大图每次输出共 13,482 小块，只解码 **2,366** 张图片，命中 **11,116** 次，缓存像素峰值 **143,942,400 字节（137.27 MiB）**。最后一次使用后释放缓存引用，缩短了驻留时间。

512 MiB 仍是缓存中像素的上限，不是进程总内存上限。工作线程持有的共享图片、两行小块、编码器和特征另占内存。PNG RGB 转换缓冲最多 1 MiB；当单行超过该大小时保留至少一行，最多处理 64 行。自动模式内存估算包含这些缓冲。

显存原始记录来自 `nvidia-smi` 的整设备采样，包含桌面及其他进程，不作为单进程显存优化证据。本轮没有改变 CUDA 算法或显存预算。

## 复现

准备私有数据库快照和特征目录，保存 v1.14.0 独立二进制，然后执行：

```powershell
python scripts/benchmark.py --exe <new-exe> --baseline-exe <old-exe> --snapshot <snapshot.db> --target <target.png> --output-dir output/compare --format jpg --write-mode batch --analysis-mode both
# PNG：--format png --write-mode stream
# CPU：--cpu --out-w 360 --out-h 640
cmake --build build --config Release --target mosaicraft_features_benchmark
build/Release/bin/mosaicraft_features_benchmark.exe <private-snapshot.db> <features-directory>
```

独立特征工具读取该固定 CPU 样本生成的 `features.meta` 作为候选集合，预热行 `run=0` 不计入中位数。精度、输出和性能验收使用关闭颜色调整的固定样本；本轮没有统一 CPU/GPU 特征算法。
