# v1.14.0 性能与稳定性验收报告

测量日期：2026-10-07 至 2026-10-08。交付类型：Windows x64 发布候选。

## 结论

固定样本通过本轮时间与匹配分数门槛。ANN 查询耗时降低 **94.4%**；三个完整场景均提速，未出现超过 5% 的总耗时回退。平均与 P90 匹配分数在日志显示精度内保持一致。CPU 场景内存下降；PNG 流式以额外缓存内存换取更少解码和更快导出，不能将其宣称为内存优化成果。

五种特征、评分权重、邻域去重规则及 CLI/API 默认值保留。CPU/GPU 特征算法统一和 CUDA 异步双缓冲留待后续质量/性能更新。

## 样本与方法

- 基线为 v1.13.10 源码，加上 `635454a` 的最小编译修复（缺失变量和作用域错误）；修复不改变匹配算法。保存独立旧版二进制用于复测。
- 新版实现提交 `651ea07`，最终包对应提交以包内 `BUILD_INFO.txt` 为准。原始记录、二进制 SHA256 和快照/目标图 SHA256 见 [采样数据](performance/v1.14.0.json)。
- 图库快照来自 `library/180x320/mosaicraft.db`，共 **45,625** 张图片；目标为 `test_input_photos/target5.png`。使用私有数据库和特征目录，原图库没有修改。
- 固定 `--topn-random 1 --benchmark --analyze`，未开启颜色调整。每次复制同一数据库快照恢复使用计数。每个版本预热一次，然后交替执行新旧版本各三次，取中位数。
- CUDA JPG/PNG 输出 **22680 × 34240**；CPU 场景使用 `--cpu --out-w 360 --out-h 640`，输出 **7200 × 12800**。
- 硬件：Ryzen 9 7940H（8 核/16 线程）、31.22 GiB 可见内存、RTX 4060 Laptop 8 GiB；Windows 10 19045、驱动 616.92、CUDA 13.3.33、VS 2026 Release。
- 完整场景测量进程墙钟时间，包含启动、分析和编码。采样循环尾部最多有约一次轮询延迟。旧版部分阶段计时范围不完整，因此不用其阶段之和冒充完整耗时。
- 最初分开采样得到旧版 JPG 中位数 22.54 s，随后同一旧版复测变为 31.58 s，说明存在整机负载漂移。最终对比采用交替采样，完整保留三次原始数据；结果适用于本机本样本。

## 时间

| 场景 | v1.13.10 基线 | v1.14.0 | 降低 |
|---|---:|---:|---:|
| CUDA · JPG batch · 13,482 小块 | 31.413 s | 25.233 s | 19.7% |
| CUDA · PNG stream · 13,482 小块 | 78.785 s | 69.943 s | 11.2% |
| CPU-only · JPG batch · 1,600 小块 | 7.462 s | 6.584 s | 11.8% |

独立 ANN 工具让两个索引使用完全相同的一批 GPU 特征查询，排除加载、特征提取、选图和输出时间：

| 检索方式 | 三次中位数 |
|---|---:|
| 708 维，串行 | 7026.590 ms |
| 196 维，串行 | 2696.620 ms |
| 196 维，默认最多 8 线程 | 396.983 ms |

全部 13,482 × 150 个候选位置与旧索引一致，196 维串并行查询结果完全一致。这是固定样本的结果，不代表所有图库的近似候选都不会变化。

首次构建另行记录：相同 45,625 条记录从空索引构建，708 维 **45.150 s**，196 维 **18.967 s**（各一次，不含磁盘保存，不能当作三次中位数）；完整应用新版首次构建与保存为 **23.790 s**。缓存文件由 **129.69 MiB** 降至 **40.58 MiB**，另有 69 字节元数据；旧 `lib.ann` 保留。

## 内存与显存

进程峰值取三个正式样本中的最大值；单位 MiB，口径为 Windows PeakWorkingSetSize。

| 场景 | 基线 | 新版 | 变化 |
|---|---:|---:|---:|
| JPG | 3367.03 | 3359.40 | -7.63 |
| PNG | 486.88 | 681.09 | +194.21 |
| CPU | 689.75 | 520.20 | -169.55 |

PNG 流式峰值上升约 194 MiB，原因是复用图片缓存；旧流式路径逐行解码。512 MiB 是缓存中像素的预算，不是进程总内存上限。两行小块、工作线程持有的图片、特征、编码器和其他数据需额外内存。自动模式估算已计入缓存、行缓冲和编码缓冲。批量编码前释放图片缓存，查询后释放索引。

`nvidia-smi` 记录的是整张设备的采样峰值，包含桌面和其他应用，WDDM 下不能据此声称单进程显存下降。CUDA JPG 的设备峰值为基线 4295 / 新版 4204 MiB，PNG 为 3683 / 3638 MiB。每次运行前的设备占用及所有峰值均保留在原始 JSON 中。新版该样本评分临时分配 **52,849,440 字节（50.40 MiB）**，低于 256 MiB 上限；极小预算测试验证了分批与失败返回。

## 复现

先准备私有数据库/特征快照，避免测量过程更新用户图库的使用计数或索引缓存。`--snapshot` 中的图片可以只读引用原文件，特征目录应为私有副本。运行旧、新版本各一次生成对应缓存，再执行：

```powershell
cmake --build build --config Release --target mosaicraft_ann_benchmark
build/Release/bin/mosaicraft_ann_benchmark.exe <snapshot.db> <target.png> <features/lib.ann> <features/lib.ann196>
# 加 --build 可记录从空索引构建的耗时。
python scripts/benchmark.py --exe <new-exe> --baseline-exe <old-exe> --snapshot <snapshot.db> --target <target.png> --output-dir output/compare --format jpg --write-mode batch
# PNG: --format png --write-mode stream
# CPU: --cpu --out-w 360 --out-h 640
```

原始记录包含预热，计算中位数时排除 `warmup=true`。细分计时只在 `--benchmark` 下启用；流式贴图和编码重叠执行，两者相加不等于墙钟时间。
