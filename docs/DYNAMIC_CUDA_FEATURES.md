# 动态尺寸 CUDA 特征提取验证

本记录对应 `05b00cf` 的特征提取更新，当时自定义尺寸仍使用 CPU 评分。后续已独立启用 CPU 兼容 CUDA 评分，当前后端行为及验收见 [独立 CUDA 评分验证](INDEPENDENT_CUDA_SCORING.md)。

本次更新保留四种模板的 CUDA 内核、线程布局和调度，在其他合法尺寸上增加 CPU 兼容的通用特征统计。特征版本仍为 v6，数据库、CLI 和 HTTP API 不变，旧自定义尺寸图库无需重建。本记录保留该阶段的独立验证结果，功能纳入 v1.14.5。

## 计算和后端

| 图库特征尺寸 / 配置 | 提取 | 评分和选图 |
| --- | --- | --- |
| 180×320、320×180、360×640、640×360 | 原模板 CUDA | 原 CUDA 评分、顺序选图 |
| 其他尺寸，宽高各 1～8192 | 通用 CUDA 整数统计，CPU OpenCV 预处理和收尾 | 原 CPU 路径 |
| `--cpu`、CPU-only 构建或计算前资源不足 | CPU | CPU |

通用核每块固定 256 线程，处理最多 4096 像素，另一个核合并各块结果。LAB 和 8×8 分区使用 64 位整数跨块累加，LBP 使用整数计数。OpenCV 的 8 位 LAB/灰度转换、TinyImage、Canny 和入库统计继续在 CPU 执行。下载统计后，CPU 按原运算顺序计算均值、转换 float 和归一化直方图；LBP 单 bin 计数在 2²⁴ 饱和，以复现原 `float += 1` 行为。

任一轴不足 8 像素时 Grid 全零；其余尺寸按原向上取整分区，空分区为零。LBP 保留八邻域比较和外边界排除。非连续 BGR ROI 通过原 OpenCV 转换读取。

建库继续使用 CPU 的顺序批次、落盘后读取、去重、事务、ID 和颜色排序。生成只替换目标特征提取；ANN、特征读取、评分、亮度过滤、邻域去重、Top-N 随机选择及分析仍用原 CPU 代码。严格一致的条件为相同 OpenCV/构建环境、输入像素、图库快照、使用计数和随机种子，不承诺跨 OpenCV 版本逐字节一致。

## 资源与失败处理

通用建库的工作缓冲预算为 64 MiB，生成纳入现有 256 MiB 主机预算。归一化 BGR、LAB、灰度、锁页输入/输出、Tiny/LBP 结果及可见 OpenCV 临时图均计入；生成还为原 CPU 匹配缓冲预留空间。设备像素、分块统计和合并输出受 256 MiB 及当前空闲显存一半的较小值约束。每批最多 256 张，随尺寸和预算缩小；默认预算下 8192×8192 会回退 CPU。

工作区准备失败或单张超预算发生在提交 CUDA 工作前，调用方继续 CPU 路径。上传、内核、CPU 收尾或同步阶段异常会等待本批任务收束后传播，清空本批输出，不用 CPU 重算掩盖故障。建库在提取成功前不开始该批数据库事务。

预算是可控缓冲的上限，不是进程 RSS 上限；完整输入/目标图、图库记录、缓存元数据、ANN、OpenCV 算子内部工作区、图片缓存及输出缓冲另计。

## 正确性验收

- CUDA 与 CPU-only 的完整 CTest 均通过：各 56 个核心测试、22 个端到端测试。CUDA 断言数为 22,657 / 29,408，CPU-only 为 18,628 / 29,379。CPU-only 中硬件专用分支按现有方式跳过。
- 通用核参数化覆盖 1×1、7×9、8×8、9×17、16×16、72×128、255×257、256×256、512×512、1537×97、8192×1、1×8192，以及非连续 ROI；五种特征和入库统计逐字段精确比较。
- 8192×2060 的高亮图加随机角落同时覆盖 LAB 总和超过 uint32、LBP 大计数超过 2²⁴，结果与原 CPU 精确一致。精确比较也会拒绝 NaN。
- 覆盖 256 张满批、尾批、工作区复用、超批拒绝、小预算、锁页/设备分配失败、上传后/CPU 任务/同步前故障及整批数据库回滚。真实 CUDA event 和传输计数确认通用核实际执行。
- Compute Sanitizer `memcheck` 运行两组通用核测试：1,382 个断言通过，设备内存错误 **0**。
- CUDA 与 CPU-only 的 Web UI/API smoke 均通过，归一化尺寸提示已更新为模板和通用 CUDA 支持范围。
- 固定种子 Top-N=3 比较纯 CPU、通用小/大批次及预算回退；覆盖自适应权重、缺失 Tiny/LBP、亮度范围 20/255、邻域去重和 35% 基础图叠加。逐块选择、PNG 文件和分析报告精确一致。
- 256×256、512×512 各用 96 张独立素材建库，再追加 16 张新素材及重复图；对比改动前 CPU、当前 CPU-only、当前 CUDA，以及旧 CPU 库直接交给新 CUDA 追加。全记录数值、Grid BLOB、独立特征文件、归一化图片字节、ID 和颜色排序一致，重复/普通重跑不改变记录。比较排除不同目录根和创建时间。
- 上述旧库的 1600 块普通/分析生成各预热一次、交替三次，共 32 次；选择序列、输出文件和解码像素全部相同。

## 性能采样

环境：Windows 10 x64、Ryzen 9 7940H（8 核 16 线程）、RTX 4060 Laptop（8188 MiB，驱动 616.92）、CUDA 13.3.33、MSVC 2026 Release、OpenCV 4.12。所有组预热一次，CPU/基线与候选交替采样三次，表中为中位数。计时期间不并行运行构建或测试。

`mosaicraft_compatible_benchmark` 使用同一批 512 张确定性随机图，CPU 和 CUDA 使用相同线程数、批量及 CPU 特征定义，计时外逐字段比较。生成特征使用 16 线程，入库特征含完整统计、使用 8 线程；源测试图预先驻留，计时不包含读图、缩放、工作区准备和落盘。完整特征阶段包含颜色转换、TinyImage、Canny、统计、传输、内核及结果收尾。

| 尺寸 | 特征工作 | CPU (ms) | 通用 CUDA (ms) | CPU / CUDA |
| --- | --- | ---: | ---: | ---: |
| 256×256 | 生成特征 | 111.04 | 96.48 | 1.151× |
| 256×256 | 入库特征及统计 | 176.09 | 154.65 | 1.139× |
| 512×512 | 生成特征 | 484.65 | 445.37 | 1.088× |
| 512×512 | 入库特征及统计 | 925.72 | 865.95 | 1.069× |

| 尺寸 / 工作 | 预处理 ms | CPU 收尾 ms | 上传 ms | 两个内核 ms | 下载 ms | 批量 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 256 / 生成 | 13.71 | 79.47 | 10.78 | 3.30 | 0.26 | 256 |

传输和内核使用 CUDA event 时间，CPU 收尾与设备任务重叠，不能相加当作墙钟时间。

端到端使用私有测试图库及相同使用计数快照。改动前 CPU 可执行文件在分支创建时保存，记录 SHA-256；它们是在当时干净工作区中已有的构建，不将其描述为本轮重新构建的基线。

| 工作 | 尺寸 | 原 CPU 总耗时 s | 通用 CUDA 总耗时 s |
| --- | --- | ---: | ---: |
| 96 张完整建库 | 256×256 | 1.262 | 1.424 |
| 96 张完整建库 | 512×512 | 7.154 | 7.087 |
| 1600 块普通生成 | 256×256 | 0.422 | 0.556 |
| 1600 块分析生成 | 256×256 | 0.851 | 1.018 |
| 1600 块普通生成 | 512×512 | 1.417 | 1.227 |
| 1600 块分析生成 | 512×512 | 2.551 | 2.730 |

特征阶段达到两种代表尺寸优于 CPU 的目标，但不保证整条命令都加速：CUDA 启动、保守批次、文件读写及分析仍有成本，256×256 的这些短任务总耗时增加。生成实测特征阶段中位数分别由约 263～267 ms 降至 234～237 ms、1008～1071 ms 降至 760～767 ms。

模板内核文件与分支起点相比无差异。四种模板补测 96 张图库、25,600 块的完整命令；另测已有私有 45,625 张图库快照、1600 块、7200×12800 JPG 输出。每组仍为一次预热和三次交替采样。

| 模板场景 | 基线总耗时 s | 当前总耗时 s | 变化 |
| --- | ---: | ---: | ---: |
| 180x320 | 1.761 | 1.716 | -2.6% |
| 320x180 | 1.797 | 1.846 | +2.7% |
| 360x640 | 5.525 | 5.599 | +1.3% |
| 640x360 | 6.715 | 6.711 | -0.1% |
| real-180x320 | 3.188 | 3.301 | +3.5% |

五组代表场景均满足总耗时回退不超过 5%，所有采样的选择和输出像素一致。源数据库快照 SHA-256 在测试前后未变。

额外的 1600 块微型图库短任务中，320×180 的进程墙钟中位数由 0.368 s 升至 0.448 s（+21.8%）；程序内部生成计时由 260.7 ms 降至 241.9 ms，差异集中在内部计时起点之外。该短样本的启动差异保留在原始数据，不据此承诺所有短命令都满足 5%。较长的同尺寸任务实测 +2.7%。

完整采样摘要和校验值保存在 [performance/dynamic-cuda-features.json](performance/dynamic-cuda-features.json)。端到端复用 `scripts/benchmark_bounded.py`，每次恢复使用计数，并使用 `--indices --pixels --skip-small`；本机私有输入、请求 JSON、基线程序、验证脚本与逐次日志位于忽略目录 `build/dynamic-cuda-validation/`。真实图库样本复用已有私有数据库/特征快照，归一化图片仅读取，源数据库不写入。
