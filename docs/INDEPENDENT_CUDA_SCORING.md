# 独立 CUDA 评分验证

基于 `05b00cf`，本次将生成过程中的提取与评分后端独立选择，为自定义尺寸默认启用 CPU 兼容 CUDA 候选评分。特征仍为 v6，CLI、HTTP API 和数据库不增加参数或字段，旧图库无需重建。本记录保留评分更新的独立验证结果，功能纳入 v1.14.5；两项新增 CUDA 能力的合并收益见 [发布性能说明](PERFORMANCE_v1.14.5.md)。

## 后端和一致性

| 场景 | 特征提取 | 候选评分 |
| --- | --- | --- |
| 四种固定模板 | 原模板 CUDA | 原 CUDA |
| 自定义尺寸、资源充足 | 通用 CUDA | CPU 兼容 CUDA |
| 提取资源不足、评分可用 | CPU | CPU 兼容 CUDA |
| 评分资源不足 | 保留可用提取后端 | CPU |
| `--cpu`、无 CUDA、CPU-only | CPU | CPU |

`cfg.useGpu` 始终表示用户意愿，不再因图片尺寸而被改写。四种模板的内核、算术、编译选项及原流水线保持不变。新评分接口只接收固定维度特征、候选索引、权重和使用次数，与图片宽高无关。

`MatchingScore.h` 集中原 CPU 基础评分表达式；`CompatibleScoring.cu` 每块 256 线程，每线程计算一个候选。Grid 和 LBP 用 `__fsub_rn` 先执行 float 减法，再提升为 double；保持平方、平方根、逐项累加、连续除法及权重相加顺序，仅新编译单元禁用 FMA、快速除法/平方根和非正规数清零。CPU 与新 CUDA 共用空间权重定义。

GPU 只输出邻域惩罚前、包含历史使用惩罚的基础分数。选图继续走原 CPU 循环：亮度过滤、邻域状态、`(分数, 图库索引)` 排序、随机数调用顺序和分析计算均保持原语义。无效候选不会进入选图，缺失 Tiny/LBP 的距离为 1。

精确一致的条件为相同标准构建/OpenCV 环境、输入特征、图库快照、使用计数和随机种子。不承诺跨 OpenCV 版本一致，也不将原模板浮点特征改为新路径语义。

## 资源和错误

主机匹配缓冲、CPU 特征缓存预算各为 256 MiB。通用提取和新评分的设备暂存合计不超过 256 MiB；评分常驻图库单独计量，准备时与暂存一起检查当时可用显存，只扣除一次本次常驻分配。已分配的提取缓冲已反映在当前空闲显存中。

新评分按最多 256 块复用工作区，联合预算包含输出分数、锁页输入/结果、上传索引以及 Reader 临时索引。先保留可用提取工作区，通过缩小批次容纳评分；评分仍不可用时只回退评分。图库按最多 4096 行复用暂存，并调用现有 FeaturePack 批量来源校验，保留缺失标志，不额外创建整库主机副本。

上传前完成资源准备。分配不足可回退相应能力，日志给出原因；图库上传、评分上传、内核或同步故障会收束 stream、禁止继续消费该工作区并传播错误。整批成功之前不公布分数，这些评分故障不会更新使用次数或覆盖既有输出。

这些预算约束可控缓冲和特征载荷；完整目标图、图库记录、ANN、缓存元数据、OpenCV 内部工作区、图片缓存及输出缓冲另计，不等于进程 RSS 上限。

## 正确性与稳定性

- CUDA 与 CPU-only 的完整 CTest 均为 2/2 通过：各 56 个核心测试、23 个回归测试。CUDA 断言数为 22,657 / 87,460；CPU-only 为 18,628 / 29,522，硬件分支在 CPU-only 中提前返回。
- 新增一组紧凑的参数化评分测试：57,858 个断言通过，覆盖随机和图像提取特征、零距离、完全平分、相邻浮点值、不同权重和使用次数、缺失 Tiny/LBP、负数及越界候选。逐分数使用精确相等，不采用误差容差。
- 复用原动态尺寸端到端测试，在普通/分析模式下运行 10 种配置，覆盖四种提取/评分组合、3 块与大批次、64 KiB 主机预算、1 MiB 联合设备预算和独立分配失败。固定种子比较 Top-N=3、自适应权重、亮度范围 20/255、邻域去重、缺失特征及 35% 叠加；逐块选择、使用计数、PNG 字节和分析报告完全相同。
- 评分工作区验证 256/1/7 块复用、超批拒绝、小预算缩批、图库/设备/锁页分配失败，以及上传、内核、同步故障。故障不会公布部分分数，必须重新准备工作区才能恢复；端到端故障保持数据库使用次数和既有输出不变。
- 真实 GPU 的 CUDA event 及传输计数确认新评分核执行。Compute Sanitizer `memcheck` 的两组评分/端到端测试共 58,228 个断言通过，设备内存错误 **0**。
- CUDA 和 CPU-only 的 Web UI/API smoke 均通过。原 `CudaBackend.cu`、`FeatureExtractorCuda.cu` 与 `05b00cf` 无差异。
- 13 组生成测试共 104 次运行（包含预热），每组选择序列、输出文件和解码像素全部一致。真实私有数据库快照测试前后 SHA-256 相同。

## 性能

以 `05b00cf` 的 Release 构建为基线，在修改源码前于干净 HEAD 执行对应构建目标并保留程序及 DLL。使用私有图库副本，每组各预热一次，交替测量三次；每次恢复相同数据库使用计数。生成关闭亮度随机调整，Top-N=1，捕获选择索引并在计时外校验输出字节和解码像素。原始数据保留预热与全部样本。

环境：Windows x64、Ryzen 9 7940H、RTX 4060 Laptop 8188 MiB（驱动 616.92）、CUDA 13.3.33、MSVC Release、OpenCV 4.12。计时期间不并行运行构建、测试或其他性能任务。

自定义图库为已有私有 CPU v6 图库，每库 96 张。代表任务为 25,600 块、150 个候选槽位（图库不足时保留无效槽位），目标与 PNG 输出均为 1280×1280，输出块 8×8；短任务为 1600 块、40 个候选、320×320 输出。使用自适应权重和 25% 基础图叠加。基线已经使用通用 CUDA 提取，差别是仍由 CPU 评分。

| 尺寸 / 模式 | 基线总耗时 s | 本次总耗时 s | 变化 |
| --- | ---: | ---: | ---: |
| 256x256 / 普通 | 4.347 | 3.252 | -25.2% |
| 256x256 / 分析 | 4.549 | 3.474 | -23.6% |
| 512x512 / 普通 | 10.950 | 10.036 | -8.3% |
| 512x512 / 分析 | 11.956 | 11.447 | -4.3% |

短任务同样保留全部样本：

| 尺寸 / 模式 | 基线 s | 本次 s | 变化 |
| --- | ---: | ---: | ---: |
| 256x256 / 普通 | 0.475 | 0.449 | -5.6% |
| 256x256 / 分析 | 0.915 | 0.791 | -13.5% |
| 512x512 / 普通 | 1.087 | 1.057 | -2.8% |
| 512x512 / 分析 | 2.027 | 1.950 | -3.8% |

独立评分基准使用 256 组真实特征和 ANN 候选，重复 32 轮，等价于每次 8192 块的评分工作量。自定义图库每块 96 个候选，45,625 张真实图库每块 150 个候选。GPU 墙钟包含打包、传输和结果复制；图库准备在计时外完成并单列，不能把评分加速倍数当作完整生成加速倍数。

| 特征来源 | 打包与复制 ms | 上传 ms | 内核 ms | 下载 ms |

四种模板使用 96 张私有图库、25,600 块和 1280×1280 PNG 输出；真实模板场景使用 45,625 张图库、1600 块和 7200×12800 JPG 输出。

## 复现

```powershell
cmake --build build --config Release --target mosaicraft_tests mosaicraft_regression_tests mosaicraft_match_benchmark mosaicraft_score_benchmark
ctest --test-dir build -C Release --output-on-failure
cmake --build build_nocuda --config Release --target mosaicraft_tests mosaicraft_regression_tests
ctest --test-dir build_nocuda -C Release --output-on-failure
cmake --build build --config Release --target mosaicraft_webui_smoke
cmake --build build_nocuda --config Release --target mosaicraft_webui_smoke
compute-sanitizer --tool memcheck --error-exitcode 86 build/Release/bin/mosaicraft_regression_tests.exe "--test-case=compatible CUDA*,dynamic CUDA keeps*"
build/Release/bin/mosaicraft_score_benchmark.exe <private-snapshot.db>
```

端到端复用 `scripts/benchmark_bounded.py`，指定 `--baseline-exe`、`--snapshot`、`--skip-small --indices --pixels`，分别设置 `--analysis-mode normal/analysis`。评分基准使用真实图库特征和 ANN 候选，CPU/GPU 同一输入、一次预热与三次交替采样，逐分数精确比较；GPU 墙钟包括主机打包、传输、内核、同步和结果复制，常驻图库准备单列。

摘要、完整样本与校验值见 [performance/independent-cuda-scoring.json](performance/independent-cuda-scoring.json)。本机私有输入、基线程序、复现请求和日志保存在忽略目录 `build/independent-cuda-validation/`。真实图库仅使用已有私有快照及只读源图片，不修改用户图库。
